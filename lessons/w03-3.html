matplotlib: fig и ax

В matplotlib два главных объекта. fig — весь холст, ax — одна система координат на нём, в которой рисуют. Пиши в объектном стиле: fig, ax = plt.subplots() и дальше методы ax.…. Так понятно, куда идёт каждая линия, а несколько графиков рядом не путаются.

Аналогия — стенгазета. fig — лист ватмана, ax — одна из заметок на нём со своими осями, подписями и легендой. Можно повесить одну заметку, а можно сетку 2 × 2. Нажимай на части рисунка — увидишь, какой строкой кода каждая создаётся.

plt.plot, plt.title рисуют на «текущих» осях — тех, что были созданы последними. С одним графиком это работает. С сеткой 2 × 2 подпись уезжает не на тот график. Правило: создал fig, ax — дальше только ax.….

СобесЧем Figure отличается от Axes?

Figure — весь холст: размер, разрешение, сохранение в файл, общий заголовок. Axes — одна область с системой координат, на ней рисуются линии, точки, столбцы, у неё свои оси, подписи и легенда. На одной Figure может быть несколько Axes. plt.subplots(nrows, ncols) создаёт Figure и массив Axes. Объектный стиль явно указывает, на каких осях рисовать, поэтому он предсказуем в сложных рисунках и функциях.

Проверь себяКакой формы axes после plt.subplots(2, 3)? Как обратиться к правому нижнему графику?

Массив numpy формы (2, 3); правый нижний — axes[1, 2] (или axes[-1, -1]).

seaborn · гистограмма, boxplot, scatter

seaborn — надстройка над matplotlib для статистических графиков: принимает DataFrame и имена столбцов, сам группирует и раскрашивает (hue=). Выбор графика начинается с вопроса. Как распределён признак — гистограмма. Отличаются ли группы — boxplot. Связаны ли два признака — scatter. Сколько в каждой категории — countplot. Как меняется во времени — lineplot.

Правила хорошего графика

Один график — одна мысль, и она в заголовке («Отчисленные кликают в 5 раз меньше уже с 1-й недели»), а не «clicks vs result». Подписаны оси и единицы. Шкала начинается с нуля у столбиков. Цвет кодирует смысл, одинаковый во всём отчёте. Для хвостатых признаков — лог-шкала, и это видно по подписи.

СобесКакой график построишь, чтобы понять, отличается ли признак у классов таргета?

Boxplot или violinplot признака по классам: видно медианы, разброс и выбросы. Плюс наложенные гистограммы или KDE с hue=target и нормировкой по группе, чтобы сравнить формы при разном размере классов. Для хвостатых признаков — в лог-шкале. Для категориального признака — доля таргета по категориям столбиками с числом объектов в категории.

Проверь себяВ scatter миллион точек слились в сплошное пятно. Что сделать?

Прозрачность (alpha=0.05), hexbin или 2D-гистограмма, или случайная подвыборка (df.sample(10_000)).

Корреляции между признаками и heatmap

Корреляция Пирсона меряет силу линейной связи от −1 до 1. Спирмен — монотонной связи: считает то же по рангам, поэтому спокоен к выбросам и хвостам. Heatmap матрицы корреляций — быстрый обзор: какие признаки дублируют друг друга и что связано с таргетом. Ноль корреляции не значит «нет связи», а высокая корреляция не значит «причина».

Как читать: зелёный — связь положительная, сиреневый — отрицательная, чем ярче, тем сильнее. Учебные данные на 400 студентов. «В зоне риска» — таргет 0/1.

r = cov(x, y) / (σx · σy)
cov — ковариация: среднее произведение отклонений от средних. Положительна, когда x и y вместе выше или вместе ниже своих средних
Деление на σ убирает единицы измерения: r не зависит от того, мерить в часах или минутах
r² — доля разброса y, которую объясняет прямая по x: r = 0.5 — это всего 25%
corr = df[NUM].corr()                          # Пирсон по умолчанию
corr_s = df[NUM].corr(method="spearman")       # по рангам: хвосты и монотонные связи
mask = np.triu(np.ones_like(corr, dtype=bool)) # верхний треугольник дублирует нижний
sns.heatmap(corr, mask=mask, annot=True, fmt=".2f", cmap="vlag", vmin=-1, vmax=1, center=0)
df[NUM].corrwith(df.target).sort_values()     # связь каждого признака с таргетом
pairs = corr.abs().where(~mask).stack().sort_values(ascending=False).head(5)  # самые похожие пары
  • Ноль корреляции ≠ нет связи. U-образная зависимость (риск высок и у тех, кто сидит слишком мало, и у тех, кто сидит слишком много) даёт r ≈ 0. Смотри scatter.
  • Корреляция ≠ причина. Клики и баллы связаны, но не потому, что клики «ставят оценку»: за обоими стоит вовлечённость. Для вывода «если увеличить X, вырастет Y» нужен эксперимент (A/B-тест).
  • Один выброс может создать или уничтожить корреляцию Пирсона. Спирмен устойчивее.
  • Пары с |r| > 0.9 — почти дубликаты. Для линейных моделей это мультиколлинеарность (урок 3.2, тема 7): оставь один признак или включи регуляризацию.
  • Категориальные признаки Пирсоном не меряют. Для «категория — таргет» смотри долю таргета по категориям, для двух категорий — Cramér's V, для числа и категории — сравнение распределений по группам.
  • Парадокс Симпсона. Связь внутри каждой группы может быть обратной к связи по всем данным: смешались группы с разным уровнем. Проверяй корреляции внутри групп (курс, семестр).
СобесЧем корреляция Пирсона отличается от Спирмена? Когда что брать?

Пирсон меряет линейную связь по самим значениям, чувствителен к выбросам и хвостам. Спирмен — это Пирсон, посчитанный по рангам: меряет любую монотонную связь (растёт одно — растёт другое, не обязательно по прямой) и устойчив к выбросам. Для хвостатых признаков вроде кликов, денег и времени, и для порядковых шкал — Спирмен. Когда важна именно линейность, например для линейной модели, — Пирсон, но вместе с графиком.

СобесКорреляция признака с таргетом 0.02. Значит, признак бесполезен?

Нет. Корреляция ловит только линейную (у Спирмена — монотонную) связь по одному признаку. Связь может быть нелинейной (U-образной), проявляться только вместе с другим признаком (взаимодействие) или только в части данных. Деревья и бустинги такие связи находят. Проверка — график зависимости, mutual information, важность признака в модели и абляция: качество на валидации с признаком и без.

Проверь себяr = 0.6. Какую долю разброса y объясняет прямая по x?

r² = 0.36, то есть 36%.

Анализ таргета и дисбаланса

Сначала смотри на таргет. Сколько классов, какие доли, нет ли пропусков, меняется ли доля со временем и по группам. Дисбаланс — когда один класс сильно реже других. Тогда accuracy обманывает, разбиение нужно стратифицировать, а метрики выбирать под редкий класс.

Как читать: 1000 студентов. Модель ловит 80% рискующих и зря тревожится о 10% остальных — она одна и та же при любой доле. Меняется только то, как её видят метрики. Нижний график появится после кнопки: сколько рискующих попадает в test из 200 строк.

Ловушка: пересэмплирование до разбиения

Сделал oversampling (размножил редкий класс) до train_test_split — копии одних и тех же студентов попали и в train, и в test. Модель «узнаёт» их, и метрика на test завышена. Любое пересэмплирование — только внутри train, а в кросс-валидации — внутри каждого фолда (imblearn.pipeline.Pipeline).

Где это в проекте

В OULAD четыре итога: Distinction, Pass, Fail, Withdrawn. Для бинарной задачи «в зоне риска» объединяешь Fail и Withdrawn. Посчитай доли сам и проверь две вещи. Сильно ли доля отличается между модулями (code_module)? Меняется ли она от семестра к семестру (code_presentation)? Если да — честная проверка — обучаться на ранних семестрах и проверять на поздних.

СобесВ данных 2% положительного класса. Что будете делать?

Не смотреть на accuracy: «все отрицательные» уже даёт 98%. Разбиение стратифицированное, при кросс-валидации — StratifiedKFold. Метрики — PR-AUC, recall при фиксированной precision или F1, ROC-AUC как дополнительная. Бейзлайн — логрег с class_weight="balanced" и бустинг со scale_pos_weight. Порог подбираю по валидации под цену ошибок. Пересэмплирование пробую только внутри train и сравниваю на валидации. Отдельно проверяю, хватает ли вообще положительных примеров. 2% от 1000 — это 20 объектов, и тогда важнее собрать данные, чем подбирать модель.

Письменные выводы по EDA

EDA заканчивается текстом, а не графиками. Хороший вывод состоит из трёх частей: факт с числом, что он значит и что ты с этим делаешь. «Клики важны» — не вывод. «У отчисленных медиана кликов за первые 4 недели в 5 раз ниже → беру клики по неделям 0–3 как признаки» — вывод.

Лаборатория · вывод или нет

Числа в утверждениях условные — это тренировка формы, а не факты про OULAD.

Шаблон раздела «EDA» в README или отчёте

## Данные
- Что в строке, сколько строк, период, источник. Что предсказываем и в какой момент времени.
## Таргет
- Доли классов; как меняются по группам и во времени → как разбиваю и какую метрику беру.
## Качество данных
- Пропуски (где, сколько, почему) → что делаю. Дубликаты, невозможные значения → что делаю.
## Что связано с таргетом
- 3–5 фактов с числами и графиком → какие признаки строю.
## Риски
- Утечки (признаки, которые знают будущее), сдвиг между train и test, малые группы.
## Следующие шаги
- Что проверю дальше и какой бейзлайн обучу первым.
  • Каждый график — с выводом в заголовке или подписи. Если вывода нет, график не нужен в отчёте. Оставь его в ноутбуке.
  • Связь — не причина. Пиши «связано», «у группы X чаще», а не «влияет» и «из-за».
  • Ограничения честно: «данные только за 2013–2014 годы», «малые группы, вывод неустойчив».
  • Утечки отдельной строкой. Самый ценный вывод EDA — найденный признак, который знает ответ заранее.

Распределение таргета и что из этого следует для разбиения и метрики. 2–3 главные находки с числами: что связано с таргетом, какие проблемы данных и как их решил. Найденные риски: утечки, сдвиг во времени. Как всё это превратилось в признаки и бейзлайн. Интервьюер проверяет, что ты думал, а не просто вызвал describe().

Окна во времени

«Сколько кликов за последние 7 дней» и «сколько с начала курса» — главные признаки проекта и две частые задачи на алгоритмической секции. Скользящее окно не пересчитывает сумму заново, а обновляет её. Префиксные суммы отвечают на любой вопрос «сколько на отрезке» за одну операцию.

Тема 8 из 15 · Алгоритмы

Скользящее окно

Окно — непрерывный кусок массива или строки, который двигается слева направо. Вместо того чтобы пересчитывать каждое окно с нуля за O(k), его обновляют за O(1): прибавили вошедший элемент, вычли вышедший. Весь проход — O(n). Бывает окно фиксированной длины и окно переменной длины, которое растёт справа и сжимается слева.

Узнать задачу на окно просто: «непрерывный подмассив» или «подстрока», и нужно найти лучший по сумме, длине или условию. Двигай шаги и сравни число операций с перебором.

# окно фиксированной длины: LeetCode 643
def max_window_sum(a, k):
    s = sum(a[:k]); best = s
    for i in range(k, len(a)):
        s += a[i] - a[i - k]           # вошёл справа, вышел слева
        best = max(best, s)
    return best

# окно переменной длины: LeetCode 209
def min_len_at_least(a, target):
    left = s = 0; best = float("inf")
    for right, x in enumerate(a):
        s += x                           # растём справа
        while s >= target:              # условие выполнено — сжимаемся слева
            best = min(best, right - left + 1)
            s -= a[left]; left += 1
    return 0 if best == float("inf") else best

  • Почему переменное окно — O(n), хотя внутри while? Каждый элемент входит в окно один раз (right) и выходит один раз (left). Итого не больше 2n шагов.
  • Когда окно не работает: переменное окно опирается на монотонность — расширил окно, и сумма не уменьшилась. С отрицательными числами это ломается, и задача «сумма ровно k» решается префиксными суммами (тема 9).
  • Окно со словарём — для строк: «самая длинная подстрока без повторов» (LeetCode 3), «есть ли перестановка p в s» (567). Внутри окна держат Counter или dict последних позиций (урок 1.3, хеш-таблица).
  • Окно с деком — максимум в каждом окне за O(n) (LeetCode 239). Это уровень medium–hard, разберём на неделе стека и очереди.
Где это в проекте

Признак «клики за последние 7 дней на момент прогноза» — скользящее окно по дням. Важно, чтобы окно смотрело только назад: rolling по умолчанию включает текущую строку и прошлые, а center=True или сдвиг назад заглядывают в будущее. Прогноз на неделю 4 строится только из недель 0–3.

СобесНайдите длину самой длинной подстроки без повторяющихся символов. Сложность?

Окно переменной длины и словарь «символ → последняя позиция». Иду right по строке. Если символ уже встречался внутри окна, сдвигаю left на позицию после его прошлого вхождения: left = max(left, last[ch] + 1). Обновляю last[ch] = right и ответ right − left + 1. Время O(n) — один проход, память O(размер алфавита). Ловушка — забыть max: старое вхождение левее окна не должно двигать left назад.

Префиксные суммы

Префиксная сумма P[i] — сумма первых i элементов. Посчитал один раз за O(n) — и сумма любого отрезка [l, r] равна P[r + 1] − P[l], одна операция. Если таких вопросов много, это решает задачу. А в паре со словарём префиксные суммы находят подмассивы с заданной суммой даже с отрицательными числами.

Аналогия — счётчик пробега в машине. Сколько проехал между Тверью и Клином? Не надо складывать каждый километр: вычти показание счётчика в Твери из показания в Клину.

from collections import defaultdict
def subarray_sum(a, k):
    seen = defaultdict(int); seen[0] = 1   # пустой префикс
    s = count = 0
    for x in a:
        s += x
        count += seen[s - k]                # был префикс, после которого сумма ровно k
        seen[s] += 1
    return count

  • Префиксы и суффиксы: «произведение всех, кроме себя» без деления (238) — произведение слева на произведение справа.
  • 2D-префиксы — сумма в любом прямоугольнике матрицы за O(1) (304). Та же идея в «интегральных изображениях» компьютерного зрения.
СобесСколько подмассивов имеют сумму ровно k? В массиве есть отрицательные числа.

Скользящее окно не подходит: с отрицательными числами сумма не растёт монотонно с расширением окна. Использую префиксные суммы и словарь «значение префикса → сколько раз встречалось», начиная с {0: 1}. Иду по массиву, накапливаю s. Число подмассивов, оканчивающихся здесь, с суммой k — это seen[s − k]. Затем увеличиваю seen[s]. Время O(n), память O(n). Перебор всех пар — O(n²).

Проверь себяa = [3, 1, 4, 1, 5]. Чему равен P и сумма отрезка [1, 3]?

P = [0, 3, 4, 8, 9, 14]. Сумма = P[4] − P[1] = 9 − 3 = 6 (1 + 4 + 1).

stash, reset и revert

stash прячет незакоммиченные правки в карман, чтобы переключиться на другую задачу. reset переносит ветку на старый коммит — переписывает историю, поэтому только для того, что ещё не запушено. revert создаёт новый коммит, который отменяет старый, — безопасно для общей истории.

СобесЧем reset отличается от revert?

reset перемещает указатель ветки на другой коммит: последующие коммиты пропадают из истории ветки, то есть история переписывается. Режимы решают, что будет с изменениями: --soft оставляет их в индексе, --mixed (по умолчанию) — в рабочей папке, --hard выбрасывает. revert ничего не удаляет: создаёт новый коммит с обратными изменениями. Для того, что уже в общей ветке, — revert. reset — для локальных, ещё не опубликованных коммитов.

Проверь себяЧто делает git stash pop, если при возврате случился конфликт?

Применяет изменения с конфликтом, который нужно разрешить, как при merge, и не удаляет запись из stash — её убирают вручную git stash drop.

Признаки «за последние 7 дней» в pandas

Таблица events: user_id, ts (datetime), amount. Для каждой строки посчитай сумму покупок этого пользователя за последние 7 дней до текущей покупки, не включая её, и накопленную сумму с начала.

Готово, когда первая покупка каждого пользователя получила 0 за 7 дней, а текущая сумма нигде не попала в «прошлое».

Решение
events = events.sort_values(["user_id", "ts"])
roll = (events.set_index("ts").groupby("user_id").amount
              .rolling("7D", closed="left").sum()     # closed="left" — без текущей строки
              .fillna(0).reset_index(level=0, drop=True))
events["sum_7d"] = roll.to_numpy()                    # порядок совпадает после sort_values
events["sum_to_date"] = events.groupby("user_id").amount.cumsum() - events.amount

Главное, что проверяют: что признак не видит текущую и будущие строки. closed="left" и «cumsum минус текущая» — это и есть «только прошлое».

  • (б) закоммитил не тот файл, ещё не запушил — переделай коммит;
  • (в) запушенный коммит сломал загрузку данных — отмени, не переписывая историю;
  • (г) сделал reset --hard и потерял коммит — верни его.

Готово, когда для каждой аварии есть команды и git log --oneline --graph выглядит так, как ты ожидал.

Команды

(а) git stash push -m "графики" → git switch main → фикс, коммит → git switch - → git stash pop. (б) git reset --soft HEAD~1, поправить индекс, снова commit — или git commit --amend. (в) git revert <hash> и push. (г) git reflog, найти хеш до reset, git reset --hard <hash>.
