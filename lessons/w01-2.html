Имена — это ярлыки на объектах

Строка a = [1, 2] не кладёт список «в a». Она создаёт объект-список и приклеивает к нему ярлык a. Строка b = a приклеивает к тому же объекту второй ярлык. Копии не появляется.

Типы подробно: что про них спрашивают

  • int не переполняется: 2 ** 1000 посчитается точно. Python сам берёт столько памяти, сколько нужно. В numpy так нельзя: np.int64 переполняется молча.
  • Деление. 7 / 2 = 3.5 — всегда float. 7 // 2 = 3 — целая часть вниз, 7 % 2 = 1 — остаток. С минусом: -7 // 2 = -4 (вниз, а не к нулю), -7 % 2 = 1. Ловят на собесе.
  • float хранится в двоичном виде, поэтому 0.1 + 0.2 == 0.3 → False (там 0.30000000000000004). Числа сравнивают с допуском: math.isclose(a, b) или np.isclose. Деньги в коде считают в копейках (int) или через decimal.Decimal.
  • round округляет к чётному: round(2.5) = 2, round(3.5) = 4. Это «банковское» округление, оно не сдвигает среднее.
  • NaN (float("nan")) — «не число», так pandas и numpy помечают пропуски. nan == nan → False. Проверяют через math.isnan(x) или pd.isna(x).
  • bool — подкласс int: True == 1, True + True == 2. Поэтому sum(p > 0.5 for p in probs) считает количество, а np.mean(y_pred == y_true) — это accuracy.
  • None — единственный объект «значения нет». Функция без return возвращает None. Проверка — только is None.
  • str — неизменяемая последовательность символов Юникода (подробно в теме 7).
  • Преобразования: int("42"), float("3.5"), str(5), int(3.9) = 3 (отбрасывает дробь, не округляет), int("3.5") → ValueError.
  • Проверка типа: isinstance(x, (int, float)), а не type(x) == int: isinstance учитывает наследование (True — тоже int).
Динамическая типизация

Тип есть у объекта, а не у имени: x = 5, потом x = "пять" — можно. Python строгий: "5" + 5 — ошибка, сам он не угадывает. Аннотации def f(x: int) -> float: ничего не проверяют при запуске, это подсказки для людей, IDE и mypy. В рабочем коде их пишут почти всегда.

Правило на всю жизнь: методы вроде append, sort, update меняют объект на месте, и это видят все его ярлыки. Операции вроде +, срезов, sorted() создают новый объект. С неизменяемыми типами (числа, строки) «изменение» всегда создаёт новый объект, поэтому ловушек нет.

  

  
Как аргументы попадают в функцию

  

    
В Python нет выбора «по значению или по ссылке». Функция получает новый ярлык на тот же объект. Отсюда два правила:

    
    
      
  • Если функция меняет изменяемый объект (lst.append), изменение видно снаружи.
    • 
      
  • Если функция перевешивает ярлык (lst = [9]), снаружи ничего не меняется: перевесили только локальный ярлык.
    • 
    

  


def add(lst):  lst.append(1)      # снаружи список изменится
def reset(lst): lst = []          # снаружи ничего не изменится

a = [1, 2]; a += [3]              # list: += меняет тот же объект (как extend)
t = (1, 2); t += (3,)             # tuple: += создаёт новый кортеж, ярлык перевешен


  
Копии: поверхностная и глубокая

  
    
    
  • b = a — не копия, второй ярлык.
    • 
    
  • a.copy(), list(a), a[:], copy.copy(a) — поверхностная копия: новый внешний список, но внутри те же объекты. Для списка чисел этого хватает.
    • 
    
  • copy.deepcopy(a) — глубокая: рекурсивно копирует всё. Нужна, когда внутри списки, словари, объекты.
    • 
  

  
Умножение списка * n тоже копирует только ярлыки. Для чисел это безопасно, для вложенных списков — нет: попробуй ответить на вопрос 2 в практике.

  
Где это ломает ML-код
df2 = df не копирует таблицу pandas. Изменишь df2 — изменится df. Нужно df2 = df.copy(). То же с numpy: срез массива — это окно в тот же массив, а не копия.

  

    
СобесПочему def f(x, acc=[]) — ловушка и как правильно?
      
Значение по умолчанию вычисляется один раз, когда выполняется строка def, а не при каждом вызове. Все вызовы без acc получают один и тот же список, и он копит значения. Правильно: def f(x, acc=None): и внутри if acc is None: acc = [].

    
СобесКак передаются аргументы в Python — по значению или по ссылке?
      
Ни так, ни так: «по ссылке на объект» (call by object reference). Функция получает ярлык на тот же объект. Изменяемый объект можно изменить внутри, и это увидят снаружи. Присваивание внутри функции перевешивает только локальный ярлык и снаружи ничего не меняет.

    
СобесЧем copy отличается от deepcopy?
      
copy создаёт новый контейнер, но кладёт в него те же вложенные объекты: изменишь вложенный список — изменится и в оригинале. deepcopy рекурсивно копирует все вложенные объекты, копия полностью независима. Цена — время и память.

    
Проверь себяЧто выведет print(0.1 + 0.2 == 0.3, -7 // 2, round(2.5))?
      
False -4 2. Двоичные дроби неточны, целочисленное деление округляет вниз, round — к чётному.

Тема 3 из 11 · Python

  
is и ==, истинность объектов

  
== спрашивает «равны ли значения». is спрашивает «это один и тот же объект, один и тот же ярлык на одном предмете».

  

    
    
      
  • [1, 2] == [1, 2] → True: значения одинаковые. [1, 2] is [1, 2] → False: это два разных списка.
    • 
      
  • is используют почти только с None: if x is None. Для чисел и строк is иногда случайно даёт True, потому что Python переиспользует маленькие числа. Полагаться на это нельзя.
    • 
    

    
Истинность. В if можно подставить любой объект. Ложными считаются: False, None, 0, 0.0, пустая строка "", пустые [], (), {}, set(). Всё остальное истинно. Поэтому пишут if not scores: вместо if len(scores) == 0:.

  

  
Ловушка
if x: и if x is not None: — разные проверки. Если x может быть 0 (например, ноль пропусков) — первая проверка считает это «нет значения». Для чисел пиши явно is not None.


  
and, or и сравнения

  
    
    
  • and и or возвращают не True/False, а один из операндов. x or y — первый истинный (или последний). x and y — первый ложный (или последний). Отсюда идиома name = user_name or "аноним". Но если 0 — допустимое значение, она его съест (та же ловушка, что выше).
    • 
    
  • Ленивость (short-circuit): x and f() не вызовет f, если x ложно. Удобно: if lst and lst[0] > 0 — не упадёт на пустом списке.
    • 
    
  • Цепочки сравнений: 0 < p < 1 работает как в математике и значит 0 < p and p < 1.
    • 
    
  • any и all: any(p > 0.9 for p in probs) — есть ли хоть один; all(...) — все ли. Обе останавливаются, как только ответ ясен. Для пустой коллекции any([]) = False, all([]) = True.
    • 
    
  • Под капотом: == вызывает метод __eq__, истинность — __bool__, а если его нет, __len__. Так свои классы учат вести себя как встроенные.
    • 
    
  • Маленькие числа и строки кешируются (от −5 до 256 и короткие строки-идентификаторы). Поэтому a = 256; b = 256; a is b → True, а с 257 может быть False. Это деталь реализации, а не правило языка.
    • 
  

  
Ловушка numpy и pandas
if df: или if np.array([1, 0]): → ValueError: The truth value ... is ambiguous. У массива нет одной истинности. Пиши явно: if not df.empty, if arr.any(), if arr.all(), if len(arr). И для условий по столбцам — &, | со скобками, а не and/or: df[(df.age > 18) & (df.debt == 0)].

  

    
СобесЧем is отличается от ==? Когда использовать is?
      
== сравнивает значения через __eq__, is проверяет, что это один объект (одинаковый id). is используют для синглтонов: None, True, False. Для чисел и строк — только ==: совпадение по is зависит от кеширования интерпретатора.

    
Проверь себяЧто вернёт [] or 0 or "x" or 5 и 1 and [] and 3?
      
"x" — первый истинный операнд. [] — первый ложный.

Условия и циклы, else у цикла

  
У циклов for и while в Python есть необычная часть else: она выполняется, если цикл дошёл до конца и не вышел через break.


for student in students:
    if student.debt:
        print("Нашли должника:", student.name)
        break
else:
    print("Должников нет")   # сработает, только если break не было

  
    
    
  • for x in коллекция — основной цикл. range(n) нужен, только когда действительно нужны числа.
    • 
    
  • while условие — когда число шагов заранее неизвестно, например в бинарном поиске.
    • 
    
  • break — выйти из цикла, continue — перейти к следующему шагу.
    • 
    
  • Тернарный оператор: label = "риск" if p > 0.5 else "норма".
    • 
  


  
Всё, что ещё нужно про условия и циклы

  
    
    
  • if / elif / else — проверяются сверху вниз, выполняется первая истинная ветка. Порядок важен: сначала узкие условия, потом широкие.
    • 
    
  • range(start, stop, step): stop не включается, как в срезах. range(10, 0, -2) → 10, 8, 6, 4, 2. range не создаёт список, он ленивый и весит одинаково для 10 и для миллиарда.
    • 
    
  • while ... else работает так же, как for ... else: else выполнится, если цикл закончился без break.
    • 
    
  • Обход словаря: for k in d — ключи, for k, v in d.items() — пары, for v in d.values() — значения.
    • 
    
  • Выйти из вложенных циклов одним break нельзя: break выходит только из ближайшего. Выносят циклы в функцию и делают return.
    • 
    
  • pass — пустая команда-заглушка там, где синтаксис требует тела.
    • 
    
  • Моржовый оператор := присваивает прямо в условии: while (line := f.readline()):.
    • 
    
  • match / case (Python 3.10+) — сопоставление с образцом, похоже на switch. Встречается редко, достаточно узнать в чужом коде.
    • 
  

  
Нельзя менять коллекцию, по которой идёшь

nums = [1, 2, 2, 3]
for x in nums:
    if x == 2:
        nums.remove(x)    # пропустит вторую двойку: элементы сдвинулись под итератором
print(nums)               # [1, 2, 3]
nums = [x for x in nums if x != 2]   # правильно: собрать новый список

  
Со словарём ещё жёстче: изменение размера во время обхода даёт RuntimeError. Обходи копию: for k in list(d):.

  
Как работает for внутри
for x in obj вызывает iter(obj) и потом next(), пока не кончится (исключение StopIteration). Поэтому for умеет ходить по чему угодно: спискам, строкам, файлам построчно, генераторам, DataLoader в PyTorch. Генератор можно пройти только один раз — второй for по нему ничего не выдаст.

  

    
СобесКогда выполняется else у цикла?
      
Когда цикл завершился сам — перебрал все элементы или условие while стало ложным, и при этом не было break. Типичное применение — поиск: break, если нашли, else — «не нашли».

Функции: значения по умолчанию, *args, **kwargs

  
*args собирает лишние позиционные аргументы в кортеж, **kwargs — лишние именованные в словарь. Звёздочки при вызове делают обратное: распаковывают.


def train(model_name, *datasets, lr=0.1, **params):
    print(model_name, datasets, lr, params)

train("catboost", "train.csv", "extra.csv", lr=0.05, depth=6, verbose=0)
# catboost ('train.csv', 'extra.csv') 0.05 {'depth': 6, 'verbose': 0}

  

    
Порядок параметров всегда такой: обычные → *args → только именованные → **kwargs.

    
Где это в ML каждый день: гиперпараметры хранят в словаре и передают модели одной звёздочкой-двойкой. Так работают конфиги, Optuna и GridSearch.

  


params = {"depth": 6, "learning_rate": 0.05, "iterations": 500}
model = CatBoostClassifier(**params)   # то же, что depth=6, learning_rate=0.05, ...

  
Ловушка из темы 1
Значение по умолчанию создаётся один раз. Изменяемые значения по умолчанию ([], {}) не используй никогда, только None. Посмотри сценарий «Ловушка def» в лаборатории выше.


  
Все виды параметров


def f(a, b, /, c, d=1, *args, e, f=2, **kwargs): ...
# a, b    — только позиционно (до /)
# c, d    — как угодно: по порядку или по имени
# *args   — все лишние позиционные
# e, f    — только по имени (после * или *args)
# **kwargs — все лишние именованные

  
    
    
  • Позиционные — по порядку: f(1, 2). Именованные — по имени: f(a=1, b=2). Позиционные всегда идут перед именованными.
    • 
    
  • Только по имени — всё после *: def split(X, *, test_size=0.2). Вызвать split(X, 0.3) нельзя, только split(X, test_size=0.3). Так защищают от путаницы, и так устроены почти все параметры sklearn.
    • 
    
  • Только позиционно — всё до /. Встречается во встроенных функциях: len(obj, /).
    • 
    
  • Распаковка при вызове: f(*[1, 2]) — как f(1, 2); f(**{"a": 1}) — как f(a=1).
    • 
  


  
Что ещё знать про функции

  
    
    
  • Возврат нескольких значений — на самом деле один кортеж: return mean, std → m, s = stats(x).
    • 
    
  • Нет return — функция вернёт None. Частая ошибка: a = a.sort() — sort меняет на месте и возвращает None, теперь a равно None.
    • 
    
  • Функции — обычные объекты. Их можно положить в переменную, список, словарь, передать в другую функцию: sorted(students, key=get_score), df.apply(clean_text).
    • 
    
  • lambda — функция в одну строку без имени: key=lambda s: s["score"]. Только одно выражение, без присваиваний. Для чего-то длиннее — обычный def.
    • 
    
  • Документация и типы:
    • 
  


def recall_at_k(y_true: list[int], scores: list[float], k: int = 10) -> float:
    """Доля положительных объектов, попавших в топ-k по скору."""

sort и sorted
a.sort() меняет список на месте и возвращает None. sorted(a) возвращает новый список и работает с любой коллекцией. Сортировка с ключом: sorted(pairs, key=lambda p: p[1], reverse=True). По двум полям: key=lambda s: (-s.score, s.name) — по убыванию балла, при равенстве по имени. Сортировка в Python стабильная: равные элементы сохраняют исходный порядок.

  

    
СобесЧто такое *args и **kwargs?
      
*args собирает лишние позиционные аргументы в кортеж, **kwargs — лишние именованные в словарь. Имена args и kwargs — соглашение, важны звёздочки. При вызове звёздочки распаковывают список и словарь в аргументы. Применение: обёртки и декораторы, которые передают аргументы дальше (def wrapper(*args, **kwargs): return func(*args, **kwargs)), конфиги гиперпараметров.

    
Проверь себяМожно ли вызвать def f(a, *, b): ... как f(1, 2)?
      
Нет: b только именованный. Нужно f(1, b=2), иначе TypeError.

Область видимости: LEGB

  
Встретив имя, Python ищет его в четырёх местах по порядку: Local (внутри функции), Enclosing (во внешней функции), Global (в модуле), Built-in (встроенные вроде len). Находит в первом — и останавливается.

x = "глобальная"

def outer():
    y = "из внешней функции"
    def inner():
        z = "локальная"
        print(z, y, x, len, w)
    inner()

Нажми на имя, чтобы увидеть путь поиска.

  

  

    
Присваивание делает имя локальным. Если внутри функции есть x = ..., то x локальная во всей функции, даже в строках до присваивания. Отсюда UnboundLocalError, он есть в практике. Чтобы изменить глобальную переменную, пишут global x, а переменную внешней функции — nonlocal y. В нормальном коде это редкость: лучше вернуть значение из функции.

    
Читать глобальную переменную можно без global, писать — нет. Изменить содержимое глобального списка (log.append(x)) тоже можно: это не присваивание имени, а вызов метода.

  


  
Замыкания

  
Внутренняя функция запоминает переменные внешней, даже когда внешняя уже завершилась. Это замыкание (closure). На нём построены декораторы, фабрики функций, колбэки.


def make_counter():
    count = 0
    def step():
        nonlocal count     # без этого count += 1 даст UnboundLocalError
        count += 1
        return count
    return step

c = make_counter()
c(); c()
print(c())                 # 3 — count живёт внутри замыкания

  
Позднее связывание: классика собеса

fs = [lambda: i for i in range(3)]
print([f() for f in fs])          # [2, 2, 2], а не [0, 1, 2]
fs = [lambda i=i: i for i in range(3)]   # [0, 1, 2]: значение зафиксировано при создании

  
Замыкание помнит не значение, а саму переменную. Функции вызываются после цикла, и все видят последнее значение i. Значение по умолчанию вычисляется в момент создания функции — поэтому второй вариант работает (тот же механизм, что в ловушке def f(x=[])).

  
    
    
  • У comprehension своя область видимости: переменная x из [x for x in a] наружу не вытекает.
    • 
    
  • А у обычного цикла — нет: после for i in range(3) переменная i существует и равна 2.
    • 
    
  • if, for, with не создают новую область видимости, в отличие от C++ и Java. Области создают только функции, классы, модули и comprehensions.
    •

СобесЧем list отличается от tuple и зачем нужен tuple?
      
tuple неизменяем: после создания нельзя добавить, удалить или заменить элемент. Поэтому он хешируемый (если внутри тоже неизменяемые объекты) и может быть ключом словаря или элементом множества. Он чуть легче по памяти и сообщает читателю: «эта запись не меняется». Функции возвращают несколько значений именно кортежем.

    
СобесПочему list не может быть ключом словаря?
      
Словарь кладёт ключ в ячейку по его хешу (урок 3). Если ключ изменится, изменится и хеш, и словарь больше не найдёт значение. Поэтому ключами могут быть только хешируемые, то есть неизменяемые, объекты. Вместо списка берут tuple.

Comprehensions

  
Comprehension — короткая запись «пройди по коллекции, отфильтруй, преобразуй, собери результат». Читается справа налево: откуда берём, что оставляем, во что превращаем.

Когда не надо
Если внутри comprehension два вложенных for, три условия и вызов с побочным эффектом (print, запись в файл) — пиши обычный цикл. Comprehension нужен для коротких понятных преобразований.


  
Где ставить if


[x for x in nums if x > 0]              # фильтр: if в КОНЦЕ, else нельзя
[x if x > 0 else 0 for x in nums]       # замена: тернарник В НАЧАЛЕ, else обязателен

  
Это два разных if. Первый решает, попадёт ли элемент в результат. Второй — во что превратится каждый элемент. Путают постоянно.

Генераторы: ленивые comprehension

  

    
    
      
  • [...] строит весь список сразу в памяти. (...) — генераторное выражение: выдаёт элементы по одному, когда их просят. Память O(1) вместо O(n).
    • 
      
  • Если генератор — единственный аргумент функции, скобки можно не дублировать: sum(x ** 2 for x in nums), max(len(w) for w in words).
    • 
      
  • Генератор одноразовый: прошёл его один раз — он пуст. Нужен дважды — сделай список.
    • 
      
  • Функция с yield вместо return — генераторная функция. Так читают огромные файлы по кусочкам и пишут батчи для обучения. Подробно — в теме генераторов позже в плане.
    • 
    

    
Скорость: comprehension быстрее цикла с append примерно в 1.5–2 раза: меньше вызовов методов в интерпретаторе. Но для чисел numpy всё равно быстрее в десятки раз (урок 1). map и filter делают то же, что comprehension, но в Python-коде их пишут реже: comprehension читается проще.

  

  

    
СобесЧем list comprehension отличается от генераторного выражения?
      
List comprehension сразу создаёт весь список в памяти, его можно обходить сколько угодно раз и брать по индексу. Генераторное выражение ленивое: вычисляет элементы по одному при обходе, занимает O(1) памяти, но проходится один раз и не поддерживает индексацию. Для больших данных и для передачи в sum, any, max берут генератор.

defaultdict: какую фабрику передать


defaultdict(int)     # счётчик: d[k] += 1
defaultdict(list)    # группировка: d[k].append(x)
defaultdict(set)     # уникальные значения на ключ: d[k].add(x)

    •

    • 
    
  • Обычный dict делает то же через d.get(k, 0) + 1 или d.setdefault(k, []), но длиннее.

deque: где пригодится

  
    
    
  • append, appendleft, pop, popleft — все O(1). rotate(k) — прокрутить по кругу.
    • 
    
  • Очередь (первым пришёл — первым ушёл): append + popleft. На ней пишут поиск в ширину (BFS) по графу — частая задача на собесе.
    • 
    
  • Стек (последним пришёл — первым ушёл): обычный list с append + pop справляется сам.
    • 
    
  • Скользящее окно: deque(maxlen=k) сама выбрасывает старые элементы. Скользящее среднее лосса, последние k событий.
    • 
    
  • Доступ к середине dq[i] — O(n). Если он нужен часто — это задача не для deque.
    • 
  

  

    
СобесЧем defaultdict отличается от dict.get и setdefault?
      
defaultdict при обращении к отсутствующему ключу вызывает фабрику и сохраняет результат в словарь. get только возвращает значение по умолчанию и ничего не сохраняет. setdefault сохраняет, но значение по умолчанию создаётся при каждом вызове, даже если ключ уже есть. defaultdict короче и быстрее для подсчётов и группировок.

def load_scores(path, cache={}):
    if path in cache:
        return cache[path]
    rows = open(path).read().split("\n")
    scores = []
    for i in range(len(rows)):
        if rows[i] != "":
            scores.append(float(rows[i].split(",")[1]))
    if scores == None or len(scores) == 0:
        print("пусто")
    cache[path] = scores
    return scores

      
Готово, когда назвал проблемы и написал исправленную версию.

      
Ответ
    
        
  • Изменяемый кеш по умолчанию. Он общий для всех вызовов и спрятан в сигнатуре. Хуже того, функция отдаёт тот же список, что лежит в кеше: вызывающий его изменит — испортит кеш. Лучше functools.lru_cache или явный кеш, а наружу отдавать копию.
    • 
        
  • Файл не закрывается. Нужен with open(path, encoding="utf-8") as f.
    • 
        
  • range(len(rows)) вместо прямого прохода for line in f.
    • 
        
  • scores == None → сравнивать с None через is. К тому же scores никогда не None, проверка мертва. Достаточно if not scores.
    • 
        
  • Заголовок CSV упадёт на float(), а ручной split ломается на кавычках. Нужен модуль csv или pandas.
    • 
        
  • print вместо ошибки или logging. Пустой файл, скорее всего, ошибка: лучше raise ValueError.


import csv
from functools import lru_cache

@lru_cache(maxsize=32)
def load_scores(path: str) -> tuple[float, ...]:
    with open(path, encoding="utf-8") as f:
        scores = tuple(float(row["score"]) for row in csv.DictReader(f))
    if not scores:
        raise ValueError(f"В {path} нет оценок")
    return scores   # tuple нельзя испортить снаружи

Ожидаемый результат и решение


from collections import Counter, defaultdict
Counter(s for s, _ in visits).most_common()
# [('Аня', 4), ('Вика', 4), ('Боря', 3), ('Гоша', 1)]
by_student = defaultdict(set)
for s, c in visits: by_student[s].add(c)
# Аня: ML, Python, SQL · Боря: ML, Python, SQL · Вика: ML, Python, SQL · Гоша: SQL
all_courses = {c for _, c in visits}

Counter(c for _, c in visits).most_common(1)               # [('Python', 5)]

169. Majority Element и 14. Longest Common Prefix

      
169. Majority Element — реши через Counter, потом скажи сложность по времени и памяти. 14. Longest Common Prefix — подсказка: zip(*strs) идёт по строкам столбцами.

      
Готово, когда оба решения приняты и ты проговорил сложность вслух.

      
Разбор


def majorityElement(nums):
    return Counter(nums).most_common(1)[0][0]       # O(n) время, O(n) память

def longestCommonPrefix(strs):
    prefix = []
    for chars in zip(*strs):          # ('f','f','f'), ('l','l','l'), ...
        if len(set(chars)) != 1:
            break
        prefix.append(chars[0])
    return "".join(prefix)            # O(суммарной длины строк)

        
Для 169 интервьюер может спросить решение за O(1) памяти. Это алгоритм голосования Бойера–Мура, его разберём позже.

«Что такое *args и **kwargs и где вы их использовали?»

      
Каким должен быть ответ
*args собирает лишние позиционные аргументы в кортеж, **kwargs — лишние именованные в словарь. При вызове звёздочки распаковывают коллекцию в аргументы. Пример из ML: гиперпараметры хранятся в словаре и передаются в модель как Model(**params). Так же устроены обёртки и декораторы, которые пробрасывают аргументы дальше: def wrapper(*args, **kwargs): return f(*args, **kwargs).
