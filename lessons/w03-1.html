Series и DataFrame

Series — это один столбец: значения плюс подписи к ним (индекс). DataFrame — таблица из нескольких Series с общим индексом. Главное отличие от списка: pandas сопоставляет данные по подписям, а не по позициям.

Представь журнал группы. Слева фамилии — это индекс (index). Сверху предметы — это столбцы (columns). Один предмет со всеми оценками — это Series. Весь журнал — это DataFrame.

Внутри каждый столбец — массив numpy (или похожий на него) одного типа. Поэтому df.score * 1.1 считается сразу для миллиона строк, без цикла на Python. Векторы из урока 2.1 (тема 1) — это ровно они.

Индекс: зачем он нужен

  • Сопоставление по подписям. Арифметика между Series и присваивание столбца df["new"] = s выравниваются по индексу. Строки не перепутаются, даже если порядок разный.
  • Быстрый поиск по ключу. df.set_index("id_student").loc[28400] — это та же хеш-таблица, что в уроке 1.3: строка находится без перебора.
  • Индекс переживает фильтр и сортировку. После df[df.score > 70] подписи остаются старыми: 0, 2, 5… Нужны 0, 1, 2 — вызови .reset_index(drop=True).
  • Индекс может быть из нескольких уровней (MultiIndex). Его даёт groupby по двум столбцам. Обычно его сразу превращают в столбцы через .reset_index().

Векторно, а не циклом

Цикл for _, row in df.iterrows() на большой таблице медленнее векторной операции в десятки и сотни раз: каждая строка становится отдельным объектом Python. Почти любая задача решается без него.

  • Арифметика и сравнения: df.a / df.b, df.score >= 70.
  • Условие: np.where(df.score >= 70, "сдал", "не сдал").
  • Замена по словарю: df.grade.map({"A": 5, "B": 4}).
  • Строки: df.name.str.lower().
  • Даты: df.date.dt.month.

apply — тот же цикл, только спрятанный. Подробно о нём — в отдельной теме дерева.

СобесЧем Series отличается от DataFrame, а DataFrame — от массива numpy?

Series — одномерный массив значений с индексом. DataFrame — набор Series с общим индексом, у каждого столбца свой тип. Массив numpy — это голые числа одного типа без подписей: строки и столбцы в нём различаются только позицией. DataFrame добавляет имена столбцов, выравнивание по индексу, разные типы в разных столбцах, работу с пропусками, группировки и склейки. Внутри столбцы — это массивы, поэтому операции такие же быстрые.

СобесПочему s1 + s2 может дать NaN, хотя пропусков в данных нет?

pandas складывает значения с одинаковыми подписями, а результат строит по объединению индексов. Если метка есть только в одной Series, пары нет, и получается NaN. Лечится так: s1.add(s2, fill_value=0), если отсутствие значит ноль; или выровнять индексы заранее. Частая причина на практике — индекс «поехал» после фильтра или reset_index только у одной из таблиц.

loc и iloc, фильтрация

loc выбирает по подписям, iloc — по номерам позиций. Фильтр — это маска из True и False: df[маска]. Условия в маске соединяют &, |, ~, а каждое условие берут в скобки.

loc — это «найди Борю по фамилии». iloc — это «дай третью строку сверху». Отсортировал журнал по баллам — Боря остался Борей, но третьей строкой теперь стал кто-то другой. Таблица ниже отсортирована по баллу, поэтому подписи идут вразнобой. Ровно так она выглядит после sort_values в реальной работе.

Ловушка: цепочка присваиваний

df[маска]["col"] = v — это две операции: сначала берётся кусок таблицы, потом меняется уже он. В pandas 2 это иногда срабатывало, иногда нет, и выдавало SettingWithCopyWarning. В pandas 3 действует Copy-on-Write: такая цепочка никогда не меняет исходную таблицу, а pandas пишет ChainedAssignmentError. На собеседованиях до сих пор спрашивают про SettingWithCopyWarning. Ответ один: присваивай через один .loc[строки, столбцы].

СобесВ чём разница между loc и iloc?

loc работает с метками: индекс и имена столбцов, срез включает правую границу, принимает маски. iloc работает с целыми позициями 0…n−1, срез как в Python — без правой границы. Пока индекс 0, 1, 2…, разницы не видно. Но после сортировки, фильтра или set_index метки и позиции расходятся, и путать их — частая тихая ошибка.

СобесЧто такое SettingWithCopyWarning и как от неё избавиться?

Это предупреждение о присваивании в объект, который может быть копией: обычно цепочка df[маска]["col"] = v или правка таблицы, полученной фильтром из другой. Исходная таблица при этом может не измениться. Исправление: менять исходную через один df.loc[маска, "col"] = v. Если нужна отдельная таблица — делать явный .copy(). В pandas 3 с Copy-on-Write цепочка гарантированно не работает, поэтому правило то же.

Пропуски

Пропуск — это не ноль и не пустая строка, а «значения нет». Сначала пойми, почему его нет. Потом решай: удалить, заполнить или оставить признак «был пропуск». Числа для заполнения считают только по train.

В pandas пропуск выглядит по-разному: NaN в числах, NaT в датах, None или NaN в строках, pd.NA в «нулевых» (nullable) типах. Проверка у всех одна — isna(). Сравнение не работает: nan == nan даёт False (урок 1.2).

Мелочь, которая удивляет: целый столбец с одним пропуском становится float. [1, None, 3] — это float64, потому что NaN — число с плавающей точкой. Нужны целые с пропусками — тип "Int64" с большой буквы.

СобесПочему заполнять пропуски средним плохо, даже если утечки нет?

Разброс признака искусственно сжимается, на гистограмме появляется пик, связи с другими признаками ослабевают. Если пропуски не случайны, среднее ещё и смещено: пропуски у «бедных» заполняются средним по «богатым». Медиана устойчивее, медиана по группе обычно ближе к правде, а флаг сохраняет информацию о самом пропуске.

groupby работает в три шага: разбить на группы, посчитать в каждой, собрать вместе (split — apply — combine). agg сворачивает группу в одну строку. transform возвращает результат каждой исходной строке — так делают признаки вида «среднее по группе».

СобесКакие бывают виды join? Чем left отличается от inner?

inner оставляет только ключи, которые есть в обеих таблицах. left — все строки левой: где пары нет, справа будут NaN. right — то же для правой. outer — объединение ключей, NaN с обеих сторон. Бывает ещё cross — каждая строка с каждой. Разница left и inner видна на студентах без оценок: в left они остаются с NaN, в inner исчезают. Если считать по inner долю сдавших, «молчащие» студенты выпадут, и результат будет завышен.

СобесПосле merge строк стало больше, чем в левой таблице. Почему и как найти причину?

В правой таблице ключ не уникален. Это либо так и задумано (один ко многим: одна строка на каждую оценку), либо дубликаты, и тогда это ошибка. Защита на будущее — validate="one_to_one" или "many_to_one": merge упадёт с понятной ошибкой вместо тихого размножения.

Физический смысл

Среднее — точка, где уравновесилась бы доска с грузами в местах значений: далёкий груз давит сильнее, как рычаг. Медиане важно только, сколько точек слева и справа, а не насколько они далеко. Поэтому один миллиардер сдвигает среднюю зарплату в стране и не трогает медианную.

СобесЧто лучше описывает типичную зарплату — среднее или медиана?

Медиана. У зарплат длинный правый хвост: немного очень больших значений тянет среднее вверх, и «средняя зарплата» оказывается выше, чем у большинства. Медиана — значение, выше и ниже которого по половине людей. Её не сдвигают крайние значения. Хорошо назвать обе: если среднее заметно больше медианы, это само по себе говорит о хвосте.

СобесКогда среднее полезнее медианы?

Когда важна сумма. Бюджет, выручка, суммарная нагрузка: сумма = среднее × n, а медиана сумму не восстанавливает. Ещё — при симметричных данных без выбросов: там среднее точнее как оценка центра, и на нём построены t-тесты и доверительные интервалы.

Дисперсия, стандартное отклонение, квантили

Дисперсия — средний квадрат отклонения от среднего. Стандартное отклонение (std, σ) — корень из неё, в тех же единицах, что и данные. Квантиль уровня q — значение, ниже которого лежит доля q данных. Медиана — квантиль 0.5, квартили — 0.25 и 0.75.

Почему n − 1

Отклонения считаются от среднего, посчитанного по этой же выборке. Выборочное среднее всегда «подстроено» под свои точки, поэтому отклонения от него в сумме чуть меньше, чем от настоящего среднего всех студентов на свете. Деление на n − 1 вместо n эту недооценку исправляет. Уже при n в сотни разницы почти нет.

Практическая ловушка: pd.Series.std() делит на n − 1 (ddof=1), а np.std — на n (ddof=0). Одни и те же данные — разные числа. Включи кнопку в лаборатории и посмотри, насколько.

На практике

В продакшене про время ответа модели говорят квантилями: «p50 — 40 мс, p99 — 300 мс». Среднее тут обманывает: 1% очень медленных запросов почти не меняет среднее, а пользователи их замечают. Квантили показывают и типичный случай, и худший.

СобесПочему в выборочной дисперсии делят на n − 1?

Потому что отклонения меряют от выборочного среднего, а оно подогнано под ту же выборку: сумма квадратов отклонений от него минимальна и меньше, чем от настоящего среднего генеральной совокупности. Деление на n систематически занижает дисперсию. Деление на n − 1 даёт несмещённую оценку. Ещё говорят, что одна степень свободы «потрачена» на оценку среднего. На больших выборках разница пренебрежимо мала.

СобесЧем стандартное отклонение отличается от IQR? Когда что брать?

σ учитывает все точки, причём отклонения в квадрате: один выброс сильно его раздувает. IQR — ширина средней половины данных, крайние значения на него не влияют вовсе. Для симметричных данных без выбросов σ информативнее, и с ним работает правило 68–95–99.7. Для данных с хвостами и выбросами — IQR и медиана: так устроены боксплот и RobustScaler.

Выбросы и IQR

Выброс — значение, сильно оторванное от остальных. Стандартное правило: всё, что дальше 1.5 × IQR от квартилей, подозрительно. «Подозрительно» не значит «удалить». Сначала выясни, ошибка это или редкий, но настоящий случай.

границы = [ Q1 − 1.5·IQR ; Q3 + 1.5·IQR ]
Q1, Q3 — края «ящика»: между ними средняя половина данных
IQR — его ширина, Q3 − Q1
1.5 — договорённость Тьюки (Tukey). Иногда берут 3 — тогда ловят только «далёкие» выбросы

Как читать ящик с усами (boxplot)

  • Ящик — от Q1 до Q3, внутри половина данных. Черта в ящике — медиана.
  • Усы тянутся до самой дальней точки, которая ещё внутри границ.
  • Точки за усами — кандидаты в выбросы.
  • Медиана не по центру ящика, а один ус длиннее — распределение перекошено.

Что делать с выбросом

  • Ошибка данных (возраст 250, отрицательная цена, 99999 как «нет данных») — исправить или превратить в NaN, дальше как с пропуском.
  • Редкий, но настоящий случай (студент сидел на платформе 60 часов) — оставить. Можно ослабить: обрезать по квантилям, взять логарифм, выбрать устойчивую модель или функцию потерь (деревья, MAE или Huber из урока 1.1).
  • Выброс и есть цель — мошенничество, поломка, аномальная активность. Тогда это не мусор, а то, что ищем.
  • Никогда не удаляй выбросы из test. Test должен быть похож на жизнь, а в жизни выбросы приходят. Границы обрезки считай по train.
СобесКак найти выбросы в признаке?

Начинаю с глаз: describe(), боксплот, гистограмма, сортировка по значению — видно, где значения невозможны физически. Формально — правило IQR: за пределами Q1 − 1.5·IQR и Q3 + 1.5·IQR. Для примерно нормальных данных можно z-оценку |z| > 3, но помню, что выбросы раздувают σ и маскируют друг друга. Для многомерных выбросов, когда каждое значение нормальное, а сочетание странное, есть Isolation Forest и LOF. Это отдельная тема.

СобесНужно ли удалять выбросы?

Не по умолчанию. Если это ошибка данных — исправляю или делаю NaN. Если это настоящие редкие значения — чаще оставляю. Для линейных моделей ослабляю их влияние: обрезка по квантилям train, логарифм, Huber-потери. Деревьям выбросы в признаках почти не мешают: важен порядок значений, а не расстояние. Удалять можно только из обучающей выборки, и проверять на валидации, стало ли лучше. Test не трогаю.

Проверь себяQ1 = 40, Q3 = 60. Где границы по правилу 1.5·IQR?

IQR = 20, границы 40 − 30 = 10 и 60 + 30 = 90.

Описательная статистика и распределения признаков

Распределение показывает, как разложены значения признака: где густо, где пусто, есть ли хвост и несколько горбов. Первый осмотр датасета — describe, доли категорий, пропуски и гистограммы. По ним решают, что чистить, что логарифмировать и чего ждать от модели.

Гистограмма делит ось на корзины (bins) и считает, сколько значений попало в каждую. Корзин мало — детали сливаются. Корзин много — видишь шум вместо формы. Переключай признаки, двигай число корзин и следи, как расходятся среднее и медиана.

Категориальные признаки

  • value_counts(normalize=True) — доли категорий. Сразу видно редкие категории и перекосы.
  • nunique() — кардинальность, то есть сколько разных значений. Регион — десяток, город — тысячи. От этого зависит, как кодировать признак (one-hot или иначе).
  • Редкие категории (меньше 1% строк) часто сливают в одну «other»: по паре строк модель ничему не научится, а на test встретит незнакомое значение.
  • Порядковые категории («0-10%», «10-20%»… или «A-level», «HE») — у них есть порядок. Его стоит сохранить, а не превращать в равноправные метки.

Где это в ML

Форма распределения влияет на модель. Линейные модели, kNN и нейросети страдают от длинных хвостов и разных масштабов (урок 2.1, тема 8). Деревьям важен только порядок значений. На проде то же самое называют дрейфом данных (data drift) и следят за ним.

СобесВам дали новый датасет. С чего начнёте?

С вопроса, что в строке и что предсказываем. Потом размер и типы: правильно ли прочиталось. Потом пропуски по столбцам и дубликаты. Потом describe по числам и value_counts по категориям: невозможные значения, константы, идентификаторы, перекосы. Дальше гистограммы и распределение таргета: дисбаланс классов. Потом связи признаков с таргетом и между собой. И отдельно ищу признаки, которые знают ответ заранее, — утечки. Итог записываю текстом: что увидел и что с этим буду делать.

СобесУ признака длинный правый хвост. Что будете делать?

Зависит от модели. Для деревьев и бустингов обычно ничего: им важен порядок значений. Для линейных моделей, kNN и нейросетей — log1p (логарифм от x + 1, работает с нулями), реже Box-Cox или Yeo-Johnson. Если на хвосте есть явные ошибки — разбираюсь с ними как с выбросами. Описываю такой признак медианой и квантилями, а не средним и σ. Если хвост в таргете (регрессия цены) — часто обучаю на log(y) и перевожу предсказание обратно.

Готово, когда:

  • у каждого merge стоит validate;
  • в ноутбуке три вывода текстом: где больше всего пропусков, какой модуль самый трудный, сколько студентов не сдали ни одного задания.
Решение
import pandas as pd
RAW = "data/raw/"
info = pd.read_csv(RAW + "studentInfo.csv")
tasks = pd.read_csv(RAW + "assessments.csv")
sa = pd.read_csv(RAW + "studentAssessment.csv")   # если пропуск записан «?», добавь na_values=["?"]

for name, t in {"info": info, "tasks": tasks, "sa": sa}.items():
    print(name, t.shape)
    print(t.isna().mean().sort_values(ascending=False).head(), "\n")

KEY = ["code_module", "code_presentation", "id_student"]
# у оценки нет курса — берём его из таблицы заданий; у задания ровно одна строка
sa = sa.merge(tasks[["id_assessment", "code_module", "code_presentation"]],
              on="id_assessment", how="left", validate="many_to_one")
per_student = (sa.groupby(KEY)
                 .agg(n_submitted=("id_assessment", "size"),
                      avg_score=("score", "mean"))
                 .reset_index())
students = info.merge(per_student, on=KEY, how="left", validate="one_to_one")
students["n_submitted"] = students.n_submitted.fillna(0).astype(int)
assert len(students) == len(info)

students["passed"] = students.final_result.isin(["Pass", "Distinction"])
students.groupby("code_module").passed.mean().sort_values()   # самый трудный модуль — сверху
(students.n_submitted == 0).sum()
students.to_parquet("data/processed/students.parquet", index=False)
