Хеш-таблица

Хеш-таблица — массив ячеек, где место для ключа вычисляется из самого ключа. Не нужно ничего перебирать: посчитал хеш — знаешь номер ячейки. Так устроены dict и set.

Представь гардероб, где номерок не выдают по очереди, а вычисляют из самого пальто: цвет, размер, бренд → номер 5. Пришёл забирать — снова посчитал номер из пальто и сразу идёшь к крючку 5. Неважно, сколько всего пальто висит.

  • Хеш-функция превращает ключ в большое число: hash("Аня"). Один и тот же ключ всегда даёт одно и то же число.
  • Номер ячейки — остаток от деления на размер массива: hash % 8.
  • Коллизия — два ключа попали в одну ячейку. Тогда их хранят рядом и сравнивают уже по-настоящему. Коллизий мало — поиск O(1). Если все ключи попали в одну ячейку, это вырождается в список и O(n).
  • Расширение. Когда ячейки заполнены примерно на две трети, таблица увеличивается и раскладывает все ключи заново. Это редкая дорогая операция, как переезд динамического массива из урока 1: амортизированно O(1).

Вот почему ключ dict обязан быть неизменяемым. Если бы можно было поменять список-ключ после вставки, его хеш изменился бы, и словарь искал бы его в другой ячейке. Значение потерялось бы навсегда.

Хеш-функция: какой она должна быть

  • Детерминированная: один ключ — всегда один хеш (в пределах запуска программы).
  • Равномерная: разбрасывает ключи по ячейкам равномерно, даже похожие («Аня1», «Аня2»). Иначе коллизии.
  • Быстрая: считается за время, пропорциональное длине ключа.
  • Главный контракт: если a == b, то hash(a) == hash(b). Обратное неверно: разные ключи могут дать один хеш, это и есть коллизия. Поэтому после хеша ключи всё равно сравниваются через ==.

Пара деталей Python:

  • hash(5) == 5, и hash(1) == hash(1.0) == hash(True): эти ключи равны по ==, поэтому {1: "a", True: "b"} — словарь из одного ключа.
  • Хеш строк случайный для каждого запуска Python (защита от атак коллизиями). Не сохраняй hash(s) в файл и не используй его для разбиения данных между запусками — бери hashlib.
  • Свой класс по умолчанию хешируется по id: два «одинаковых» объекта — разные ключи. Чтобы сравнивались по полям, определяют __eq__ и __hash__ вместе или пишут @dataclass(frozen=True).

Как разрешают коллизии

СпособКак работаетГде

Открытая адресацияячейка занята — ищем другую свободную по правилу (следующую или по формуле)Python dict и set

Коэффициент заполнения (load factor) — доля занятых ячеек. Чем он выше, тем больше коллизий и медленнее поиск. Поэтому таблица всегда держит запас пустых ячеек и расширяется заранее. Отсюда «цена памяти» у dict и set, о которой говорили в уроке 1.

Хеши за пределами dict

  • Криптографические хеши (hashlib.sha256, md5) — длинные и стабильные между запусками и компьютерами. Ими проверяют, что файл не изменился, находят дубликаты файлов, разбивают пользователей на группы A/B-теста: int(sha256(user_id)) % 100 < 50.
  • Feature hashing в ML: миллион разных слов кладут в 2²⁰ признаков по хешу слова, без хранения словаря (HashingVectorizer в sklearn). Коллизии терпят ради памяти.
  • Кеш: @functools.lru_cache запоминает результаты функции в словаре по аргументам, поэтому аргументы должны быть хешируемыми. Основа мемоизации в динамическом программировании.
  • Хеш-индексы в базах данных и df.set_index("id") в pandas — та же идея: найти строку по ключу без перебора.
СобесКак устроен dict в Python? Почему поиск за O(1)? Когда он бывает O(n)?

dict — хеш-таблица. По ключу считается хеш, из него — индекс ячейки, туда и кладётся пара ключ–значение. При поиске хеш считается заново, и мы сразу идём в нужную ячейку, поэтому в среднем O(1). При коллизии Python пробует другие ячейки по детерминированному правилу (открытая адресация) и сравнивает ключи через ==. Когда таблица заполнена примерно на 2/3, она увеличивается, и ключи раскладываются заново, это амортизированно O(1). O(n) — если много ключей дают коллизии, например из-за плохой хеш-функции или специально подобранных ключей.

Проверь себяПочему set не сохраняет порядок, а list сохраняет?

В set место элемента определяет хеш, а не очередь добавления. В list элементы лежат подряд в порядке добавления. Обычный dict с Python 3.7 сохраняет порядок вставки: он хранит пары отдельно в массиве, а хеш-таблица держит только номера.

СобесМогут ли два разных ключа иметь одинаковый хеш? Что тогда?

Да, это коллизия: ключей бесконечно много, а ячеек конечно. Таблица хранит оба ключа (в цепочке или в соседних ячейках) и при поиске сравнивает найденный ключ с искомым через ==. Обязательное правило обратное: равные объекты обязаны иметь равные хеши.

Проверь себяСколько ключей в словаре {1: "a", 1.0: "b", True: "c"} и какое значение?

Один ключ 1 со значением "c": все три равны по == и имеют одинаковый хеш. Ключ остаётся первым вставленным, значение — последним.

Хеширование: Two Sum, Contains Duplicate, Valid Anagram

Паттерн звучит так: «запоминай увиденное в dict или set и спрашивай о нём за O(1)». Он превращает перебор всех пар за O(n²) в один проход за O(n). Это самый частый паттерн первых задач на собеседовании.

Лаборатория · Two Sum по шагамnums = [3, 8, 1, 6, 4], target = 10
что ищем на этом шаге
seen — уже видели: число → индекс

Перебор всех пар для 5 чисел — до 10 сравнений, для 10 000 — до 50 миллионов. Один проход со словарём — 5 и 10 000 шагов.

# 1. Two Sum — индексы двух чисел с суммой target. O(n) время, O(n) память
def twoSum(nums, target):
    seen = {}                          # число → индекс
    for i, x in enumerate(nums):
        if target - x in seen:         # пара уже встречалась?
            return [seen[target - x], i]
        seen[x] = i

# 217. Contains Duplicate — есть ли повтор. O(n) / O(n)
def containsDuplicate(nums):
    return len(set(nums)) != len(nums)

# 242. Valid Anagram — одинаковые ли буквы. O(n) / O(1): алфавит ограничен
def isAnagram(s, t):
    return Counter(s) == Counter(t)
Ловушка в Two Sum

Проверяй target - x in seen до того, как добавить x в seen. Иначе при target = 8 и x = 4 найдёшь пару «4 и та же самая 4».

Как узнать, что задача на хеширование

Сигналы в условии:

  • «есть ли», «встречался ли раньше», «найти дубликат» → set;
  • «сколько раз», «самый частый», «одинаковые ли наборы» → Counter / dict-счётчик;
  • «найти пару с суммой / разностью», «индекс того, что видели» → dict значение → индекс;
  • «сгруппировать по признаку» → defaultdict(list) с правильным ключом;
  • наивное решение — два вложенных цикла, а во внутреннем ты ищешь что-то → почти наверняка этот поиск заменяется словарём.

Частые ошибки

Вернул значения вместо индексов. Отсортировал массив в Two Sum и потерял исходные индексы. Забыл про пустой ввод. Использовал list как ключ (нужен tuple). Сказал «O(1) памяти», создав словарь на n элементов.

СобесКак решить Two Sum без дополнительной памяти?

Если можно менять порядок и нужны значения, а не индексы: отсортировать и идти двумя указателями с концов. Сумма меньше target — левый вправо, больше — правый влево. O(n log n) по времени из-за сортировки, O(1) дополнительной памяти. Если нужны исходные индексы — сортировать пары (значение, индекс), тогда память O(n).

LeetCode 75 или NeetCode 150: как решать

Бери NeetCode 150: задачи сгруппированы по паттернам, ровно как ветки твоего дерева, и к каждой есть видеоразбор. 3–4 задачи в неделю по теме недели, и к январю ты пройдёшь основные паттерны.

Как решать задачу на собеседовании. Порядок важнее скорости. Интервьюер оценивает, как ты думаешь, а не только итоговый код.

1Переспроси условие. Могут ли быть отрицательные числа, повторы, пустой ввод? Что вернуть, если ответа нет?
2Пример руками. Возьми маленький пример и реши его на бумаге. Часто идея появляется именно тут.
3Перебор вслух. «Можно проверить все пары, это O(n²)». Даже наивное решение — уже результат.
4Ускорение. «Что я делаю много раз? Какая структура сделает это за O(1)?» Для первой недели ответ почти всегда — dict или set.
5Код. Понятные имена, без лишнего. Проговаривай, что пишешь.
6Прогони тесты глазами. Обычный случай, пустой ввод, один элемент, повторы. Назови сложность по времени и памяти.
Правило 25 минут

Не решилась за 25 минут — открывай разбор, не мучайся час. Разберись, закрой и напиши решение сам. Через 3 дня реши её ещё раз с нуля. Решённая с третьего раза задача запоминается лучше, чем решённая с первого.

LeetCode 75 и NeetCode 150: в чём разница

  • LeetCode 75 — официальный список LeetCode, короче, перемешан по темам. Хорош как быстрый обзор.
  • NeetCode 150 — сгруппирован по паттернам и идёт от простого к сложному, у каждой задачи видеоразбор. Для учёбы по паттернам удобнее, поэтому выбран он.
  • Порядок разделов NeetCode: Arrays & Hashing → Two Pointers → Sliding Window → Stack → Binary Search → Linked List → Trees → Heap → Backtracking → Graphs → Dynamic Programming. Для стажировки в ML важнее всего первые пять и деревья/графы на базовом уровне.

Что оценивают на алгоритмической секции

  • Решение задачи — пришёл ли к работающему и эффективному решению.
  • Коммуникация — объяснял ли ход мыслей, задавал ли уточняющие вопросы, реагировал ли на подсказки.
  • Качество кода — понятные имена, нет копипасты, разумная структура.
  • Проверка — сам ли нашёл баги, прогнал крайние случаи, назвал сложность.

Во многих компаниях код пишут в простом редакторе без запуска и без автодополнения. Тренируйся так же: сначала напиши решение целиком, прогони глазами, и только потом нажимай Submit. Каждая неудачная отправка на LeetCode — это баг, который на собеседовании нашёл бы интервьюер.

Терминал

Терминал — разговор с компьютером текстом. Ты всегда «стоишь» в какой-то папке, и команды работают относительно неё. Серверы с GPU, Docker, git — всё это терминал, мышки там нет.

Флаги, маски и справка

  • Флаги меняют поведение команды: ls -l (подробно), -a (скрытые, они начинаются с точки), можно склеивать: -la. Длинные пишутся через два дефиса: --help.
  • Справка: команда --help или man команда (выход — q).
  • Маски: * — любые символы, ? — один символ. ls data/*.csv, rm logs/run_?.txt. Маску раскрывает терминал до запуска команды.
  • Пробелы в именах — в кавычки: cd "My Project". Поэтому файлы проектов называют без пробелов.

Пайпы и перенаправление

Главная сила терминала — склеивать маленькие команды. | (пайп) передаёт вывод одной команды на вход следующей.

python train.py > log.txt          # вывод в файл (перезаписать)
python train.py >> log.txt         # дописать в конец
python train.py > log.txt 2>&1     # и ошибки тоже: 2 — поток ошибок, 1 — обычный вывод
cut -d, -f3 data.csv | sort | uniq -c | sort -rn | head   # топ значений 3-го столбца CSV
history | grep pip                 # какие pip-команды я запускал
tail -f log.txt                    # смотреть лог обучения вживую (Ctrl+C — выйти)

Что ещё нужно в первый рабочий день

  • Горячие клавиши: Ctrl+C — прервать команду, Ctrl+R — поиск по истории, стрелка вверх — прошлая команда, Ctrl+L или clear — очистить экран.
  • Переменные окружения: echo $HOME, export CUDA_VISIBLE_DEVICES=0. В них же хранят секреты: export OPENAI_API_KEY=..., а в Python читают os.environ["..."] — так ключи не попадают в код и git.
  • PATH — список папок, где терминал ищет программы. which python покажет, какой Python запустится. Если там не .venv — окружение не активировано.
  • Права: chmod +x run.sh — сделать скрипт запускаемым, потом ./run.sh.
  • Удалённый сервер: ssh user@host — зайти на сервер с GPU, scp file user@host:path — скопировать файл. Долгое обучение запускают в tmux или через nohup python train.py &, чтобы оно не умерло, когда закроешь ноутбук.
rm — навсегда

rm -rf папка удаляет без корзины и без вопросов. Перед ним — pwd и ls, чтобы убедиться, где ты. Никогда не пиши rm -rf с переменной, которая может оказаться пустой, и с / или ~ в пути.

СобесКак найти все строки с ошибками в большом логе и посчитать, сколько их?

grep -i "error" train.log — показать, grep -ic "error" train.log — посчитать. Последние ошибки: grep -i error train.log | tail -20. Следить в реальном времени: tail -f train.log | grep -i error.

Проверь себяЧем > отличается от >> и от |?

> записывает вывод в файл, стирая старое; >> дописывает в конец; | передаёт вывод не в файл, а на вход другой команде.

Git

Git — машина времени для кода. Каждый коммит — снимок проекта, к которому можно вернуться. Между «изменил файл» и «сохранил снимок» есть промежуточная зона: ты сам выбираешь, что войдёт в снимок.

Лаборатория · три зоны git
Рабочая папкафайлы, как ты их видишь
Stagingчто войдёт в коммит
Репозиторийистория коммитов

  

  

    
Основной цикл каждый день: git status → git add файл → git commit -m "что сделано" → git push. git log --oneline показывает историю, git diff — что изменилось и ещё не добавлено.

    
Сообщения коммитов пиши в стиле Conventional Commits: feat: add validation split, fix: use val set for early stopping, docs: metrics table in README. По истории сразу видно, что происходило.

  

  
  

    
Ветки — параллельные линии истории. Новую фичу делают в своей ветке: git switch -c feature/validation. main в это время остаётся рабочей. Готово — сливаешь: git switch main, потом git merge feature/validation. Если обе ветки меняли одни и те же строки — будет конфликт, git покажет оба варианта, и ты выберешь.

    
Remote — копия репозитория на GitHub. git clone url — скачать проект целиком. git push — отправить свои коммиты. git pull — забрать чужие. На работе в main напрямую не пушат: пушат ветку и открывают Pull Request, коллеги его смотрят.

  

  
Что не коммитят
Данные, обученные модели, папку .venv, __pycache__, .ipynb_checkpoints и, главное, секреты: пароли, токены, ключи API. Всё это перечисляют в .gitignore до первого коммита. Секрет, однажды попавший в историю, считается утёкшим, даже если потом удалить файл.


  
Как устроен коммит

  
    
    
  • У каждого коммита есть хеш (a3f9c21) — его уникальное имя, посчитанное из содержимого. Тот же принцип, что в первой теме урока.
    • 
    
  • Коммит хранит снимок файлов, автора, время, сообщение и ссылку на родителя — предыдущий коммит. История — цепочка коммитов.
    • 
    
  • Ветка — просто подвижный указатель на коммит. Новый коммит в ветке передвигает указатель вперёд. Поэтому ветки в git создаются мгновенно.
    • 
    
  • HEAD — указатель «где я сейчас»: обычно на текущую ветку.
    • 
  


  
Посмотреть и отменить


git diff                    # что изменено и ещё НЕ в staging
git diff --staged           # что уже в staging и войдёт в коммит
git log --oneline --graph   # история с ветками
git show a3f9c21            # что было в конкретном коммите

git restore файл            # выбросить изменения в файле (вернуть как в последнем коммите)
git restore --staged файл   # убрать из staging, изменения останутся
git commit --amend          # поправить ПОСЛЕДНИЙ коммит (сообщение или забытый файл)
git reset --soft HEAD~1     # отменить последний коммит, изменения останутся в staging
git reset --hard HEAD~1     # отменить коммит И стереть изменения — осторожно
git revert a3f9c21          # новый коммит, отменяющий старый. Безопасно для уже запушенного
git stash / git stash pop   # спрятать незакоммиченное, переключиться, вернуть

  
Главное правило
Коммиты, которые уже запушены и которые могли забрать коллеги, не переписывай: никаких reset, --amend и rebase поверх них. Для отмены есть git revert. Переписывать можно только свою локальную историю.

merge, rebase, fetch, pull

  

    
КомандаЧто делаетКогда

    
      
mergeсоединяет ветки коммитом слияния, история сохраняется как была, с развилкойпо умолчанию; безопасно

      
fast-forwardесли в main ничего нового не было, git просто передвигает указатель, без коммита слиянияпроисходит сам

      
rebaseпереносит твои коммиты поверх свежего main, будто ты начал позже. История прямаяобновить свою ветку перед PR; только для своих незапушенных или личных веток

      
fetchскачивает новое с GitHub, но ничего не меняет в твоих файлахпосмотреть, что нового

      
pullfetch + merge (или rebase, если настроено)забрать и сразу влить

    

  
origin — стандартное имя удалённого репозитория. origin/main — твоя локальная копия того, каким main был на GitHub при последнем fetch. git push -u origin ветка в первый раз связывает локальную ветку с удалённой, дальше хватает git push. Fork — своя копия чужого репозитория на GitHub, так вносят вклад в open source.

  
.gitignore — шаблоны, по строке: data/ — папка целиком, *.pkl — по расширению, !data/README.md — исключение из правила. Файл, который уже закоммичен, gitignore не спрячет: сначала git rm --cached файл.

  

    
СобесЧем merge отличается от rebase?
      
Оба вносят изменения одной ветки в другую. merge создаёт коммит слияния и сохраняет историю как есть, с развилкой. rebase переписывает твои коммиты поверх целевой ветки — история получается прямой, но у коммитов меняются хеши. Поэтому rebase не делают с коммитами, которые уже есть у других.

    
СобесКак отменить последний коммит?
      
Если он ещё не запушен: git reset --soft HEAD~1 (изменения останутся) или --hard (стереть). Если уже запушен: git revert <хеш> — новый коммит, отменяющий изменения, история не переписывается. Поправить только сообщение или добавить забытый файл — git commit --amend до пуша.

    
Проверь себяЧем git fetch отличается от git pull?
      
fetch только скачивает новые коммиты в origin/... и ничего не трогает в рабочей папке. pull делает fetch и сразу сливает изменения в текущую ветку.

Виртуальное окружение и requirements.txt

  
venv — отдельная папка с Python и библиотеками для одного проекта. requirements.txt — список этих библиотек с версиями, чтобы любой человек и любой сервер собрал точно такое же окружение.

  

    
Без venv
Все проекты делят одни библиотеки. Старому проекту нужен pandas 1.5, новому — 2.2. Обновил для нового — сломался старый.

    
С venv
У каждого проекта своя папка .venv со своими версиями. Проекты не мешают друг другу, а удалить окружение — просто удалить папку.

  


python3 -m venv .venv               # создать окружение в папке проекта
source .venv/bin/activate           # включить: в начале строки появится (.venv)
pip install pandas scikit-learn     # ставится только в это окружение
pip freeze > requirements.txt       # записать точные версии всего установленного
pip install -r requirements.txt     # собрать окружение по списку на другом компьютере
deactivate                          # выключить

  
Фиксируй версии через ==. pandas>=2.2 через полгода установит pandas 3.0, и код может сломаться без единого изменения с твоей стороны. pandas==2.2.3 воспроизводит ровно то, что работало. В VS Code выбери интерпретатор из .venv (Cmd+Shift+P → Python: Select Interpreter), иначе редактор будет ругаться на импорты.

  
Где это у тебя
В BRS сейчас >= во всех строках requirements.txt. Это пункт из разбора проекта, и его легко починить после этой темы.


  
Как это работает внутри

  

    
venv — это папка с ссылкой на Python и собственной site-packages, куда pip кладёт библиотеки. activate всего лишь ставит .venv/bin первым в PATH (тема «Терминал»), поэтому команды python и pip находятся там. Проверка: which python должен показывать путь внутри .venv.

    
Самая частая ошибка новичка — ModuleNotFoundError, хотя «я же ставил». Библиотеку поставили в одно окружение, а запускают из другого. Надёжная форма установки: python -m pip install ... — pip того же Python, которым запускаешь.

  


  
pip: команды на каждый день


pip list                         # что установлено
pip show pandas                  # версия, где лежит, от чего зависит
pip install "pandas==2.2.3"      # конкретная версия
pip install -U pandas            # обновить
pip uninstall pandas

  
Почему pip freeze — не идеал. Он записывает всё установленное, включая десятки зависимостей зависимостей. Файл раздувается, а на другой ОС часть пакетов может не встать. Хорошая практика — в requirements.txt руками перечислить то, что импортирует твой код, с версиями через ==. Для больших проектов есть инструменты с lock-файлом, о них ниже.


  
venv, conda, poetry, uv: что выбрать

  

    
ИнструментЧто этоКогда

    
      
venv + pipвстроено в Python, ничего ставить не надоучёба, небольшие проекты, по умолчанию

      
condaокружение + свой менеджер пакетов, умеет ставить и не-Python вещи (CUDA, системные библиотеки) и разные версии Pythonнаучный стек, GPU, Windows

      
poetry, uvзависимости в pyproject.toml + точный lock-файл. uv ещё и очень быстрыйкомандная разработка, библиотеки, прод

      
Dockerизолирует не только Python, а всю систему целикомдеплой модели, одинаковая среда на сервере (позже в плане)

    

  
    
    
  • Версия Python тоже важна: requirements.txt её не фиксирует. Её пишут в README или файл .python-version.
    • 
    
  • Jupyter и venv: чтобы ноутбук видел библиотеки окружения, поставь в него ipykernel и выбери ядро .venv в VS Code или Jupyter.
    • 
    
  • PyTorch с GPU ставят командой с сайта pytorch.org под свою версию CUDA — обычный pip install torch может поставить не ту сборку.
    • 
  

  

    
СобесЗачем нужно виртуальное окружение?
      
Изолировать зависимости проекта: у каждого проекта свои версии библиотек, они не конфликтуют между собой и с системным Python. Вместе с requirements.txt или lock-файлом это даёт воспроизводимость: любой участник и сервер собирают ту же среду, и «у меня работает» перестаёт быть проблемой.

Отладчик

  
Отладчик останавливает программу на нужной строке и даёт посмотреть все переменные в этот момент. Это быстрее и честнее, чем расставлять print по всему коду.

  

    
Лаборатория · отладка по шагам

    

      

      

        
Переменные

        
Watch: len(scores)

        
Стек вызовов

      

    

    

      
    

    

    
Щёлкни по номеру строки, чтобы поставить или убрать точку останова (красная точка). Задача: найди, на каком студенте и почему программа падает.

  

  
    
    
  • Breakpoint (F9 или клик слева от номера строки) — остановиться здесь.
    • 
    
  • Step Over — выполнить строку целиком, не заходя внутрь функций. Step Into — зайти внутрь вызываемой функции. Step Out — доработать текущую функцию и выйти к месту вызова.
    • 
    
  • Watch — выражение, которое пересчитывается на каждом шаге.
    • 
    
  • Условная точка останова (правый клик по точке → Edit Condition): например, len(scores) == 0. Незаменима, когда ошибка случается на 900-й итерации из 1000.
    • 
    
  • В Jupyter отладчик тоже есть, но для скриптов привычнее VS Code: F5, конфигурация «Python File».
    •

Отладка ML-кода

  
    
    
  • Форма прежде всего: половина ошибок — несовпадение размеров. Смотри X.shape, y.shape, df.info(), df.isna().sum().
    • 
    
  • Начни с маленького: 100 строк вместо миллиона, 1 эпоха вместо 50. Ошибка найдётся за секунды, а не за час.
    • 
    
  • Переобучись на одном батче: если нейросеть не может выучить 10 примеров до нулевой ошибки, в коде баг.
    • 
    
  • Зафиксируй случайность (random_state=42), иначе баг будет то появляться, то нет.
    • 
    
  • assert для проверок по ходу: assert X_train.shape[0] == len(y_train), assert not set(train_ids) & set(test_ids).
    • 
    
  • logging вместо print в скриптах, которые живут долго: уровни (DEBUG, INFO, ERROR), время, запись в файл, и не надо удалять отладочные print перед коммитом.
    • 
  

  

    
СобесМодель обучилась, но метрики подозрительно плохие. Как будете искать проблему?
      
Сначала данные: формы X и y, совпадает ли порядок строк, нет ли пропусков, правильно ли закодирован таргет, нет ли перепутанных столбцов. Потом сравнить с бейзлайном (DummyClassifier): если не лучше — баг в данных или в разбиении. Проверить на маленькой выборке, что модель может переобучиться. Посмотреть на конкретные ошибочные примеры глазами. Код проверить отладчиком или assert-ами, а не догадками.

Практика · как на собеседовании и в работе

Разбор Group Anagrams


from collections import defaultdict
def groupAnagrams(strs):
    groups = defaultdict(list)
    for w in strs:
        groups[tuple(sorted(w))].append(w)   # ключ — отсортированные буквы
    return list(groups.values())
# O(n · k log k), где k — длина слова. Ключ — tuple, потому что list нельзя хешировать

        
Ускорение до O(n · k): ключом сделать кортеж из 26 счётчиков букв.


    
Собес · устно · 3 минуты
      
«Что происходит, когда вы пишете d["Аня"] = 5?»

      
Готово, когда в ответе есть хеш, индекс ячейки, коллизии, расширение и сложность.

      
Каким должен быть ответ
Python считает hash("Аня"), по нему находит ячейку внутренней таблицы. Если она свободна — кладёт ключ, хеш и значение. Если там другой ключ — коллизия, Python пробует следующие ячейки по своему правилу, пока не найдёт свободную или тот же ключ (тогда перезаписывает значение). Если таблица заполнилась примерно на 2/3, она увеличивается и ключи раскладываются заново. В среднем O(1), амортизированно с учётом расширений.
