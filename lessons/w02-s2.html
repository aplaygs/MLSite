Имя — это ярлык, а не коробка

12 мин

Зачем: половина «странных» багов в Python — из-за того, что два имени смотрят на один и тот же список. Поменял через одно — поменялось и в другом. В тесте недели 1 на этом были два вопроса.

Представь, что объекты — это вещи на полке, а имена переменных — ярлыки на ниточках. Запись b = a не копирует вещь: она вешает второй ярлык на ту же самую вещь.

Дальше всё зависит от вещи. Список, словарь, множество можно менять на месте — и это увидят все ярлыки. Число, строку, кортеж поменять нельзя: «изменение» создаёт новый объект, и ярлык перевешивается на него.

Лаборатория · карта памяти по шагам
b = aвторой ярлык на тот же объект — не копия
b = a.copy()новая вещь — копия списка (или list(a), a[:])
b.append(3), b += [3]меняют список на месте — видно через все ярлыки
b = b + [3]создаёт новый список и перевешивает только b
def f(acc=None)список по умолчанию — только так: [] в def создаётся один раз на все вызовы
Так это называютимена — ссылки на объекты; список и словарь — изменяемые (mutable), число, строка, кортеж — неизменяемые (immutable). Ловушка с acc=[] — mutable default argument.

b = a — тот же объект. Нужна копия — a.copy(). Список по умолчанию — None, а внутри новый [].

Подробнее: функция получает тот же список, копия бывает «неглубокой» · 4 минуты

В функцию передаётся тот же объект, а не копия. Поэтому функция, которая меняет список на месте, меняет его и у того, кто её вызвал:

def add_bonus(scores):
    scores.append(100)          # меняем на месте

my = [70, 80]
add_bonus(my)
print(my)                       # [70, 80, 100] — список изменился снаружи!

Правило хорошего тона: функция либо возвращает новый объект, либо явно говорит в названии, что меняет (sort() меняет, sorted() — нет).

copy() — неглубокая копия. Она копирует только внешний список, а вложенные списки остаются общими:

a = [[1, 2], [3]]
b = a.copy()
b[0].append(9)
print(a)                        # [[1, 2, 9], [3]] — внутренний список общий
import copy
c = copy.deepcopy(a)            # полная копия на всех уровнях (подробно — неделя 3)

Проверить, один ли это объект: id(a) == id(b) или a is b. id — «номер» объекта в памяти, как #1 в карте памяти выше.

Кортеж неизменяемый, но если внутри лежит список, сам список менять можно: t = ([1], 2); t[0].append(5) работает. Поэтому такой кортеж нельзя сделать ключом словаря.

Частые ошибки
  • b = a # «скопировал»b = a.copy()b = a — это второй ярлык, а не копия.
  • def f(x, acc=[]):def f(x, acc=None):Список по умолчанию один на все вызовы.
  • def clean(rows): rows.remove(...)def clean(rows): return [r for r in rows if ...]Функция молча портит список вызывающего.

Типы: числа, строки и дробные, которые врут

8 мин

Зачем: в данных постоянно приходят числа строками («5» из CSV), а сравнение дробных через == ломает проверки в ML-коде.

Пять типов, которые встречаются везде: int (целое), float (дробное), str (строка), bool (True / False) и None — «значения нет». Узнать тип — type(x).

  • 7 / 2 → 3.5 — обычное деление всегда даёт float. 7 // 2 → 3 — целая часть. 7 % 2 → 1 — остаток.
  • "5" + "1" → "51" — строки склеиваются. Сначала превратить в число: int("5") + 1 → 6.
  • Дробные хранятся неточно, потому что компьютер считает в двоичной системе: 0.1 + 0.2 → 0.30000000000000004. Поэтому дробные сравнивают с допуском.
0.1 + 0.2 == 0.3               # False!
import math
math.isclose(0.1 + 0.2, 0.3)   # True — равны с маленьким допуском
abs((0.1 + 0.2) - 0.3) < 1e-9  # то же самое руками
Так это называютчисла с плавающей точкой (floating point, стандарт IEEE 754); превращение типов — приведение (casting): int(), float(), str().

Дробные через == не сравнивают — только math.isclose. Из CSV всё приходит строками.

Подробнее: округление, int() и bool — тоже число · 3 минуты
  • int("3.5") — ошибка ValueError. Сначала float("3.5"), потом int(...). int(3.9) — 3: дробная часть отбрасывается, не округляется.
  • round(2.5) — 2, а round(3.5) — 4: Python округляет «половинки» к чётному. Для денег и отчётов это бывает неожиданностью. round(x, 2) — до двух знаков.
  • int в Python не переполняется: 2 ** 100 посчитается точно. float держит около 15–16 значащих цифр.
  • bool — это почти число: True + True — 2. Отсюда удобный приём: sum(r == "Pass" for r in results) считает, сколько Pass.
  • Проверить тип: isinstance(x, int) (лучше, чем type(x) == int). Подсказать тип в коде: def mean(xs: list[float]) -> float: — это аннотации, Python их не проверяет, но редактор и коллеги понимают код быстрее.
  • float("nan") — «не число», так в данных обозначают пропуск. Оно не равно даже самому себе: x != x — True. В pandas (неделя 4) пропуски будут именно такими.

== или is, и что Python считает «ложью»

8 мин

Зачем: проверка if n_missing: молча путает «пропусков ноль» с «значения нет». В данных это классическая ошибка.

== спрашивает: одинаковые ли значения? is спрашивает: это одна и та же вещь (один объект)? Два разных списка [1, 2] равны по ==, но is даёт False.

На практике is нужен ровно для одного: проверить None — x is None, x is not None. Всё остальное — через ==.

Python умеет ставить в if что угодно. Считаются ложью: 0, 0.0, "", [], {}, None, False. Всё остальное — правда, даже "0" и [0].

n_missing = 0
if n_missing:                 # 0 — ложь: сюда не зайдём, хотя число есть
    ...
if n_missing is not None:     # правильно: «значение задано», даже если это 0
    ...
Так это называют== — равенство (equality), is — тождество (identity); то, что Python считает ложью, — falsy, остальное — truthy.

None проверяют только через is. «Пустое» и «ноль» — тоже ложь, поэтому if x: — не проверка на None.

Подробнее: почему is иногда «работает» с числами, and / or и all / any · 3 минуты
  • a = 256; b = 256; a is b — True, а с 1000 может быть False: маленькие числа Python хранит в одном экземпляре для экономии. Это деталь реализации — числа и строки никогда не сравнивают через is.
  • Почему для None именно is: у объекта можно переопределить ==. Например, у массивов NumPy arr == None вернёт массив из True и False, а не один ответ. is переопределить нельзя.
  • 1 == 1.0 — True: числа разных типов сравниваются по значению.
  • a or b возвращает первое «правдивое» значение: name = user_name or "гость". Ловушка та же: если user_name — пустая строка или 0, подставится запасное.
  • all(xs) — все правда, any(xs) — хоть одно: any(r["final_result"] == "Fail" for r in rows).
Частые ошибки
  • if x == None:if x is None:
  • if count: # count может быть 0if count is not None:0 — ложь.
  • if name is "Аня":if name == "Аня":Строки — только через ==.

Где живёт имя: внутри функции и снаружи

8 мин

Зачем: ошибка UnboundLocalError и «почему функция не видит мою переменную» — частые вопросы на первой работе и на собеседовании.

У функции своя комната. Имена, которым внутри функции что-то присваивают, живут только в этой комнате. Прочитать имя снаружи функция может, а вот присвоить ему — уже нет: присваивание сразу делает имя «своим», внутренним.

Ищет Python по порядку: сначала в своей функции, потом во внешней функции (если одна внутри другой), потом в файле, потом среди встроенных (len, print).

total = 10
def show():
    print(total)          # читать снаружи можно → 10

count = 0
def add():
    count = count + 1     # UnboundLocalError: count внутри — своя, а ей ещё ничего не присвоили

def add(count):           # правильно: получить через параметр…
    return count + 1      # …и вернуть через return
count = add(count)

Если очень нужно поменять внешнее имя изнутри, есть два слова. global count — «count из файла, не создавай свою». nonlocal count — «count из внешней функции» (когда функция внутри функции). Работают, но делают код запутанным: функция меняет что-то незаметно для читающего. В 9 случаях из 10 правильнее параметр и return.

count = 0
def add():
    global count           # берём count из файла
    count += 1

def make_counter():
    n = 0
    def step():
        nonlocal n         # n из make_counter
        n += 1
        return n
    return step
Ловушка: функция помнит имя, а не значение

Функция, созданная в цикле, смотрит на переменную цикла в момент вызова, а не в момент создания. fs = [lambda: i for i in range(3)] — все три функции вернут 2: когда их вызвали, цикл уже закончился и i = 2. Починка: lambda i=i: i — значение сохраняется в параметре.

Так это называютобласть видимости (scope); порядок поиска — LEGB: Local → Enclosing → Global → Built-in. Функция, которая помнит внешние имена, — замыкание (closure).

Данные в функцию — через параметры, наружу — через return. global почти никогда не нужен.

Частые ошибки
  • list = [1, 2, 3]nums = [1, 2, 3]Имя list перекрыло встроенную функцию: list("abc") дальше сломается. То же с sum, max, id, type, input.
  • def f(): total += xdef f(total, x): return total + xUnboundLocalError — или используй параметр и return.
  • lambda: i # в циклеlambda i=i: iИначе все функции увидят последнее i.

Строки: срезы, методы и f-строки

11 мин

Зачем: срезы — это «первые 5 строк», «последние 3 недели», «каждый второй элемент». В pandas и NumPy (недели 4–5) они работают так же.

Запись s[start:stop:step]: с start включительно, до stop не включая, с шагом step. Пропущенное — значит «с начала», «до конца», «шаг 1». Отрицательные номера считают с конца: -1 — последний.

  • s[:3] — первые три · s[-3:] — последние три · s[::2] — каждый второй · s[::-1] — задом наперёд.
Лаборатория · покрути срез
s =
s[::] →

Методы строк — то, чем чистят данные. Строки неизменяемые, поэтому каждый метод возвращает новую строку:

" Pass \n".strip()"Pass" — убрать пробелы и переносы по краям
"PASS".lower()"pass"; есть и .upper(), .title()
"AAA,2013J,Pass".split(",")['AAA', '2013J', 'Pass'] — разрезать
", ".join(["ML", "SQL"])"ML, SQL" — склеить список
"10-20%".replace("%", "")"10-20" — заменить
name.startswith("w0")начинается ли с …; есть и endswith(".csv")

f-строки — вставить значения прямо в текст. Буква f перед кавычкой, выражения — в фигурных скобках, после двоеточия — формат:

acc, n = 0.87342, 32593
f"accuracy {acc:.3f} на {n:,} студентах"   # 'accuracy 0.873 на 32,593 студентах'
f"{acc:.1%}"                                # '87.3%'
f"{n=}"                                     # 'n=32593' — удобно при отладке
Так это называютсрез (slice); у строк, списков и кортежей одинаковый синтаксис. Срез списка — копия: a[:].

stop не включается: s[1:5] — это 4 элемента, с 1-го по 4-й. Методы строк возвращают новую строку. Числа в тексте — через f"{x:.2f}".

Подробнее: строки неизменяемые, in, len и форматы чисел · 2 минуты
  • s[0] = "P" — ошибка: строку нельзя поменять на месте. Только собрать новую: s = "P" + s[1:].
  • "ML" in "Learning ML" — True: in у строки ищет подстроку. len(s) — длина.
  • Склеивать много строк через + в цикле медленно — собери список и сделай "".join(parts).
  • Форматы: {x:.2f} — 2 знака после точки, {x:,} — разделитель тысяч, {x:.1%} — проценты, {s:>10} — выровнять вправо на 10 символов.
  • Срез списка — новый список (копия), срез строки — новая строка. Срез никогда не падает с ошибкой «вышли за границу»: "abc"[1:100] — просто "bc". А вот "abc"[100] — IndexError.

Две функции без ловушек

  1. safe_mean(values): среднее списка, а для пустого списка — None. Проверь: safe_mean([]), safe_mean([0, 0]) — во втором случае должен быть 0, а не None.
  2. add_score(score, scores=None): добавляет оценку в список и возвращает его. Вызови дважды без второго аргумента — списки не должны «слипаться».
Решение
def safe_mean(values):
    if not values:              # пустой список — ложь
        return None
    return sum(values) / len(values)

m = safe_mean([0, 0])
if m is not None:               # не «if m:» — иначе 0 потеряется
    print("среднее", m)

def add_score(score, scores=None):
    if scores is None:
        scores = []             # новый список на каждый вызов
    scores.append(score)
    return scores

На собеседовании

Так спрашивают на отборах на стажировку. Сначала ответь вслух сам, потом открой ответ.

СобеседованиеПочему def f(x, acc=[]) — плохая идея?

Значение по умолчанию вычисляется один раз, когда Python выполняет def. Список создаётся один и общий для всех вызовов, поэтому данные из прошлых вызовов «прилипают». Правильно: acc=None, а внутри if acc is None: acc = [].

СобеседованиеЧем отличаются == и is?

== сравнивает значения, is — проверяет, что это один и тот же объект в памяти. is используют только для None (и True/False как синглтонов); числа и строки через is не сравнивают — результат зависит от деталей реализации.

СобеседованиеЧем list отличается от tuple?

list изменяемый — можно добавлять и менять элементы; tuple неизменяемый. Поэтому tuple можно сделать ключом словаря или элементом set (если внутри тоже неизменяемое), а list нельзя. tuple берут для фиксированных записей, например (код курса, год).

СобеседованиеЧто такое поверхностная копия?

Копия только внешнего контейнера: a.copy(), list(a), a[:]. Вложенные объекты остаются общими — изменишь вложенный список в копии, он изменится и в оригинале. Полную копию делает copy.deepcopy.

  1. Ярлыки: b = a — тот же объект. Копия — a.copy(). append и += меняют список на месте, b = b + [3] — новый список.
  2. Список по умолчанию: def f(acc=None): if acc is None: acc = [].
  3. Типы: 7 / 2 = 3.5, 7 // 2 = 3, 7 % 2 = 1. "5" + "1" = "51" — из CSV всё строки.
  4. Дробные: 0.1 + 0.2 != 0.3 — сравнивай math.isclose.
  5. is — только для None. Ложь: 0, 0.0, "", [], {}, None, False. if x: — не проверка на None.
  6. Функции: присваивание внутри — своё имя. Данные — через параметры и return. Функция помнит имя, а не значение.
  7. Строки: срезы [start:stop:step], stop не включается, [::-1] — задом наперёд; методы strip, lower, split, join, replace возвращают новую строку; f"{x:.2f}", f"{x:,}", f"{x:.1%}".
  8. global / nonlocal — поменять внешнее имя; почти всегда лучше параметр и return. Не называй переменные list, sum, max, id.
