Где я: терминал — это чат с компьютером

8 мин

Зачем: на серверах, где обучают модели, нет мышки и окон — только терминал. И на собеседовании спросят хотя бы базовые команды.

Терминал — окно, в котором ты пишешь команду, а компьютер отвечает текстом. Как в чате.

Главное, что надо понять: ты всегда «стоишь» в какой-то папке. Как в Finder, только без картинок. Все команды работают относительно этой папки.

pwdгде я сейчас — полный путь к папке
lsчто лежит в этой папке
cd projectsзайти в папку projects
cd ..выйти на уровень вверх
cd ~вернуться домой, в свою папку пользователя
Так это называюттекущая папка (working directory) — где ты стоишь; путь — адрес файла: полный /Users/vlad/projects или от текущей папки projects/oulad-risk.

pwd — где я, ls — что тут, cd — перейти. Потерялся — pwd.

Файлы: создать, скопировать, перенести, удалить

8 мин

Зачем: скачал данные — их надо положить в проект. Разложил неправильно — переложить. Это пять команд, которые ты будешь набирать каждый день.

mkdir reportsсоздать папку
cp откуда кудаскопировать (оригинал остаётся)
mv откуда кудаперенести или переименовать (оригинала больше нет)
rm файлудалить файл; папку — rm -r папка
cat файлпоказать, что внутри файла
Осторожно

rm удаляет сразу, без корзины. Отменить нельзя. Поэтому перед rm -r всегда смотри pwd и ls: точно ли ты там, где думаешь.

Найти нужное: find и grep

7 мин

Зачем: в чужом проекте сотни файлов. Тимлид говорит: «посмотри, где мы читаем данные». Листать всё руками — час. Командой — секунда.

Два вида поиска — запомни их через почту:

  • find ищет коробку по надписи на ней — файл по имени. «Все файлы, которые заканчиваются на .csv».
  • grep ищет фразу внутри писем — текст внутри файлов. «Где в коде написано read_csv».
find . -name "*.csv"все CSV в этой папке и вложенных; точка — «отсюда», звёздочка — «что угодно»
grep -rn read_csv .где встречается read_csv; -r — во всех вложенных папках, -n — с номером строки

Своё окружение: у каждого проекта свой рюкзак

8 мин

Зачем: без этого проекты ломают друг друга. Это первое, что делают в любом новом проекте, и частый вопрос на собеседовании: «зачем нужен venv?».

Python на компьютере один, а проектов много. Старому проекту нужен pandas 1.5, новому — 2.2. Если ставить всё в один общий Python, обновил для нового — сломался старый.

Решение — у каждого проекта свой рюкзак с библиотеками: папка .venv внутри проекта. Включил её — pip install кладёт библиотеки только в этот рюкзак. Другие проекты не задеты.

python3 -m venv .venvсоздать рюкзак (один раз на проект)
source .venv/bin/activateнадеть его — в начале строки появится (.venv)
pip install pandasпоставить библиотеку в этот проект
deactivateснять рюкзак
Так это называютвиртуальное окружение (virtual environment, venv) — изолированный набор библиотек проекта. Зависимости — библиотеки, без которых проект не работает.

5

Список библиотек: requirements.txt

7 мин

Зачем: коллега скачал твой проект. Какие библиотеки ему ставить и каких версий? Ответ — один файл. Без него проект «работает только у тебя».

Рюкзак .venv тяжёлый и свой на каждом компьютере, его не пересылают. Пересылают список покупок — файл requirements.txt: какие библиотеки и каких точно версий.

Ты сохраняешь список, коллега по нему ставит у себя ровно то же.

pip freeze > requirements.txtзаписать всё, что стоит в окружении, в файл; > — «вывод не на экран, а в файл»
pip install -r requirements.txtколлега: поставить всё по списку

Внутри файла строки вида pandas==2.2.3. Два знака равно — именно эта версия. Без версии через полгода поставится новая — и код может сломаться, хотя ты ничего не менял.

Работа · 15 минут

Заготовка проекта на твоём Mac

  1. Создай папку ~/projects/sandbox и зайди в неё.
  2. Создай окружение, включи его, поставь pandas.
  3. Сохрани requirements.txt и посмотри его через cat.
  4. Найди через find все файлы .py в своей папке ~/Downloads.

Готово, когда в начале строки видно (.venv), а в requirements.txt есть строка с pandas==.

Все команды подряд
mkdir -p ~/projects/sandbox && cd ~/projects/sandbox
python3 -m venv .venv
source .venv/bin/activate
pip install pandas
pip freeze > requirements.txt
cat requirements.txt
find ~/Downloads -name "*.py"

mkdir -p не ругается, если папка уже есть, и создаёт промежуточные папки. && — «если первое получилось, сделай второе».

Итог

  1. pwd · ls · cd — где я, что тут, перейти. cd .. — вверх, cd ~ — домой.
  2. mkdir · cp · mv · rm — создать, скопировать, перенести, удалить. rm без корзины, папки — с -r.
  3. find — файл по имени, grep -rn — текст внутри файлов.
  4. venv — у каждого проекта свои библиотеки: python3 -m venv .venv → source .venv/bin/activate.
  5. requirements.txt — список с точными версиями (==): pip freeze > сохранить, pip install -r поставить. В git кладут список, а не .venv.
