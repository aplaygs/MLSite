Git — точки сохранения, как в игре

10 мин

Зачем: без git любая правка — шаг без страховки. С ним можно сломать что угодно и вернуться. Им пользуется любая команда, и на собеседовании его знание просто подразумевают.

В игре ты сохраняешься перед боссом. В git то же самое: коммит — точка сохранения всего проекта, с подписью, что поменялось.

Сохранение идёт в два шага. Сначала отбираешь, что войдёт в сохранение (git add). Потом сохраняешь с подписью (git commit). Зачем два шага: поменял три файла, а сохранить хочешь только один — остальные доделаешь потом.

git initначать следить за папкой (один раз)
git statusчто изменилось и что уже отобрано — смотри его постоянно
git add файлотобрать файл в сохранение; git add . — всё
git commit -m "что сделал"сохранить с подписью
git log --onelineсписок сохранений
Так это называютрепозиторий — папка под присмотром git; индекс (staging) — «отобрано в сохранение»; коммит — само сохранение.

status → add → commit. Подпись — что сделал: «add data loader», а не «правки».

Ветки: пробовать, не ломая рабочее

8 мин

Зачем: хочешь попробовать новую модель, а рабочая версия должна оставаться рабочей. Ветка — параллельная копия истории для эксперимента.

Главная ветка — main: здесь то, что работает. Для новой задачи делаешь ветку, коммитишь в неё сколько угодно. Получилось — сливаешь обратно в main. Не получилось — просто бросаешь ветку, main не задет.

git switch -c new-modelсоздать ветку и перейти в неё
git switch mainвернуться в main
git branchсписок веток, звёздочка — где ты
git merge new-modelвлить ветку в текущую (стоять надо в main)

GitHub: облако для твоих сохранений

8 мин

Зачем: GitHub — копия репозитория в интернете. Так работают в команде, и по нему тебя оценивают на отборе: проекты в резюме — это ссылки на GitHub.

Git живёт у тебя на компьютере. GitHub — тот же репозиторий на сервере. Между ними три действия:

  • clone — скачать чужой (или свой) репозиторий целиком, с историей;
  • push — отправить свои новые коммиты на GitHub;
  • pull — забрать чужие новые коммиты к себе.

Правило команды: перед работой — pull, после — push. Если коллега успел отправить что-то раньше, git не даст сделать push, пока ты не заберёшь его изменения.

Так это называютremote — удалённая копия, обычно с именем origin; локальный репозиторий — тот, что у тебя.

Отладчик: остановить код и посмотреть

8 мин

Зачем: код не падает, но выдаёт неправильное число. print-ами можно искать час. Отладчик за минуту покажет, в какой строке значения пошли не туда.

Отладчик — это пауза в программе. Ставишь точку остановки на строке. Код доходит до неё и замирает. Дальше идёшь по одной строке и смотришь, как меняются переменные.

Функция ниже должна считать средний балл. Для [80, 90, 70] ждём 80, а она выдаёт 23.3. Нажимай «Шаг» и смотри справа на total: где она перестаёт расти, там и ошибка.

Как тренироваться и когда подаваться

6 мин

Зачем: на отборах в большие компании почти всегда есть секция с алгоритмическими задачами. Её не берут знаниями — её берут регулярной тренировкой.

Какой список задач. Решать «всё подряд» на LeetCode бессмысленно. Бери один готовый список:

  • LeetCode 75 — официальный учебный план LeetCode, 75 задач. Хорош для старта.
  • NeetCode 150 — 150 задач, сгруппированы по приёмам (хеш-таблица, два указателя, окно…), к каждой есть видеоразбор.

Как решать одну задачу:

  • 25 минут сам — на бумаге идея, потом код.
  • Не вышло — смотри только идею решения, не код. Пиши сам.
  • Через 3 дня реши эту же задачу снова, не подглядывая.
  • Темп: одна задача в день лучше, чем десять в выходные.

Когда подаваться. На летние стажировки в крупных компаниях наборы обычно идут осенью и зимой, у некоторых — весной. Точные даты по компаниям собраны на странице «Отборы». Перенеси их в календарь с напоминанием за неделю.

Твой sandbox на GitHub

  1. В папке ~/projects/sandbox из прошлого урока сделай git init.
  2. Создай файл .gitignore со строкой .venv/ — чтобы окружение не попало в git.
  3. Закоммить .gitignore и requirements.txt.
  4. На github.com создай пустой репозиторий sandbox и отправь туда коммит.

Готово, когда на странице репозитория на GitHub видны два файла, а папки .venv там нет.

Команды
cd ~/projects/sandbox
git init
echo ".venv/" > .gitignore
git add .gitignore requirements.txt
git commit -m "chore: init sandbox"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/sandbox.git
git push -u origin main

При первом push GitHub попросит войти. Проще всего поставить GitHub CLI (brew install gh) и один раз выполнить gh auth login.

Итог

  1. Коммит — точка сохранения: git status → git add → git commit -m "что сделал"; история — git log --oneline.
  2. Ветка — эксперимент без риска: git switch -c имя, потом в main git merge имя.
  3. GitHub: clone — скачать, pull — забрать чужое, push — отправить своё. Перед работой pull, после — push.
  4. Отладчик: точка остановки → шаг за шагом → смотри переменные. F10 — следующая строка, F11 — внутрь функции.
  5. Тренировка: один список (LeetCode 75 или NeetCode 150), 25 минут сам, повтор через 3 дня. Сроки наборов — в календарь.
