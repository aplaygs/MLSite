    Проекты

    Два проекта на этом дереве

    Один сюжет для резюме: «делаю ML-инструменты для учёбы». Проекты закрывают темы плана на практике, задачи по ним стоят в дорожке «Проект» каждой недели. Подробный разбор — в Obsidian, «BRS — разбор и новая концепция».

    А · Ранняя диагностика академического риска

    недели 2–9 Реальные открытые данные OULAD: оценки и активность студентов по дням.
    Предсказать на неделе N курса, что студент провалит курс, чтобы куратор успел вмешаться. Валидация во времени: учимся на прошлых семестрах, проверяем на следующем.
    EDA → бейзлайн (константа, логрегрессия) → CatBoost → PR-AUC и порог под recall → калибровка → SHAP-карточки → FastAPI в Docker → README с ограничениями.

    Б · Помощник по документам вуза (RAG)

    недели 10–11 Открытые документы МИРЭА: положения, правила, учебные планы.
    Ответы со ссылкой на источник. Главное — оценка качества на своём наборе из 50–100 вопросов: Recall@k и MRR для поиска, проверка ответов.
    Разбор PDF → нарезка → эмбеддинги → поиск FAISS или Qdrant вместе с BM25 → реранкинг → LLM с цитатами.
    Что было не так в первой версии BRS — повод для честного рассказа на собеседовании
    1. Тестовая выборка участвует в обучении. eval_set=(X_test, y_test): CatBoost выбрал лучшую итерацию по тесту и сохранил 136 деревьев из 250. Метрики на тесте завышены. Нужна отдельная валидационная выборка. Валидация →
    2. Нет бейзлайна. Простая логистическая регрессия обгоняет CatBoost по PR-AUC (0.938 против 0.887): таргет в генераторе — линейная формула. Бейзлайн →
    3. Модель учит формулу, которую ты сам задал. Данные синтетические. avg_lab_score в формулу риска не входит, но получил 10% важности, то есть модель подстраивается под шум. Первый вопрос на интервью будет «откуда данные». EDA и утечки →
    4. Порог 0.5 при 8% положительных. Recall 0.75: каждого четвёртого студента в зоне риска модель пропускает. Для раннего предупреждения порог подбирают под recall. Выбор порога →
    5. В тесте 24 положительных примера. Одна ошибка сдвигает метрику на несколько пунктов. Нужна кросс-валидация. k-fold →
    6. Код без структуры. Всё на уровне модуля, пути относительные, predict.py пустой и не в git, версии в requirements не зафиксированы. Инженерия кода →
    7. README обещает шесть модулей, а готова часть одного. Опиши то, что работает, остальное вынеси в раздел «Планы». Портфолио →

    Где что лежит

    • Файлы недель — 60_Машинное обучение/План ML. Галочки там и здесь одни и те же.

    Как пользоваться

    • На компьютере — эта страница: удобно смотреть всё дерево и отмечать.
    • С телефона — файл недели в Obsidian: те же темы и галочки.
    • Неделя тяжёлая в вузе — не догоняй всё сразу: ◆ ключевые первыми, остальное уйдёт в хвосты.
    • В воскресенье агент собирает план недели и смотрит хвосты.
